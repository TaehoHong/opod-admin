# 게시물 이미지 평가 기준

작성일: 2026-09-29

이 문서는 게시물 이미지의 자연스러움과 제작 품질을 평가하는 공통 기준이다.
이번 세션에서 확인한 사용자 품질 기준과 평가상의 주의점을 정리한다.
특정 캐릭터, 소재, 촬영 방식, 이미지 모델에만 적용되는 처방은 포함하지 않는다.
평가 기준의 정리이며 자동 평가 Agent, 재시도 루프, 게시 승인 단계의 추가를 뜻하지 않는다.

## 1. 목표와 기준점

목표는 **실제 개인 SNS에 섞였을 때 사람이 그 상황에서 찍은 사진처럼 보이는 이미지**다.
다른 생성 이미지보다 낫다는 상대평가를 합격 기준으로 사용하지 않는다.

- 이미지가 예쁘거나 선명한 것, 지시를 잘 따른 것과 자연스러운 것은 별개다.
- 큰 신체 오류나 눈에 띄는 합성 경계가 없다는 사실만으로 합격시키지 않는다.
- 개별 요소가 그럴듯해도 전체 장면이 인공적으로 조립된 인상을 주면 목표 미달이다.
- 평가자가 정확한 원인을 설명하지 못하더라도 자연스러움의 실패를 인정할 수 있다.
  원인을 아직 모른다는 이유로 품질 판정을 완화하지 않는다.
- 기준이 되는 실제 사진은 계정의 의도된 촬영·표현 스타일과 비교 가능해야 한다.
  비교 사진을 보지 않았다면 실제 SNS와 대조했다고 기록하지 않는다.

이번 세션의 평가 보정: 오류가 적고 구도가 성립한다는 이유로 자연스러움을
과대평가했다. 앞으로는 이러한 기술적 성립을 최소 조건으로만 취급한다.

## 2. 별도로 평가할 네 가지 항목

| 항목 | 판단할 질문 | 다른 항목으로 대체할 수 없는 이유 |
| --- | --- | --- |
| 자연스러움 | 한 장의 사진으로 믿을 만하며 사람이 실제로 찍은 인상인가? | 정체성과 프롬프트를 잘 지켜도 합성처럼 보일 수 있다. |
| 기획·스타일 준수 | 필요한 피사체, 행동, 구도, 표현 의도와 계정 스타일이 반영됐는가? | 자연스러워도 다른 장면이나 다른 스타일이면 목적을 달성하지 못한다. |
| 정체성 유지 | 보이는 범위에서 동일한 인물·대상의 식별 특징이 유지됐는가? | 닮았다는 이유로 원본의 조명·의상·포즈까지 복제해도 되는 것은 아니다. |
| 컷 사이 연속성 | 실제로 같아야 하는 요소는 이어지고 달라져도 되는 요소는 자유로운가? | 각 사진이 자연스러워도 묶음의 동일성이 깨질 수 있다. |

인물이 없는 사진에는 인물 정체성을 평가하지 않는다. 한 장이거나 서로 독립된
장면이라면 불필요한 연속성 요구를 만들지 않는다. 적용되지 않는 항목은 해당 없음으로 남긴다.

## 3. 자연스러움 평가 항목

아래 항목은 관찰을 돕는 기준이다. 모든 항목을 생성 프롬프트에 넣을 체크리스트가 아니다.

| 관점 | 확인할 내용 |
| --- | --- |
| 전체 장면 | 피사체와 공간이 같은 순간에 함께 촬영된 것처럼 보이는가? 각각 좋은 요소를 조립한 장면처럼 보이지 않는가? |
| 빛과 색 | 인물·사물·배경의 밝기, 빛의 방향과 부드러움, 그림자, 반사광이 하나의 공간에서 성립하는가? |
| 질감과 선명도 | 피부·머리카락·옷감·주변 물체의 질감과 세부 묘사가 같은 촬영 결과로 느껴지는가? 일부만 별도로 보정하거나 렌더링한 인상이 강하지 않은가? |
| 공간과 접촉 | 원근, 크기, 거리, 가림, 반사, 접촉과 그림자가 서로 맞는가? 인물이나 물체가 공간에 실제로 놓여 있는가? |
| 신체와 행동 | 자세, 무게중심, 손의 사용, 관절과 사물의 관계가 장면에 맞는가? 오류가 없더라도 지나치게 굳거나 설명을 위해 만든 동작처럼 보이지 않는가? |
| 촬영의 설득력 | 시점·시야·프레이밍·시선·피사체와 카메라의 관계가 실제 촬영으로 성립하는가? 의도한 촬영 방식과 결과가 맞는가? |
| 정돈과 연출 | 얼굴, 머리, 옷, 배경까지 모든 요소가 일률적으로 이상화되면서 인공적인 인상을 만들지 않는가? 의도된 연출 수준과 맞는가? |
| 배경과 세부 구조 | 주변 구조, 물체와 글자가 장면 안에서 일관되는가? 작게 보이는 부분까지 모두 정밀해야 한다는 요구를 만들지는 않는다. |

관찰할 때 지킬 원칙:

- 같은 공간에서도 재질·거리·광원에 따라 색과 밝기는 다를 수 있다.
  피부와 배경의 색이 다르다는 사실만으로 조명 오류라고 단정하지 않는다.
- 매끈한 피부, 정돈된 머리, 선명한 피사체, 흐린 배경은 각각 단독으로 실패 근거가 아니다.
  장면 전체와 의도된 스타일에서 어떻게 결합되는지 본다.
- 예쁜 외모, 성적 매력, 노출 있는 패션, 의도적인 포즈는 합성감과 별개다.
  자연스러움을 이유로 캐릭터의 표현 방향을 순화하지 않는다.
- 카메라를 보거나 포즈를 잡았다는 이유로 부자연스럽다고 판단하지 않는다.
  우연히 찍힌 듯한 사진만을 정답으로 삼지 않는다.
- 연출된 사진도 자연스러울 수 있다. 전문 촬영이나 보정 자체를 일괄 금지하지 않고
  이번 게시물이 의도한 표현 수준에 맞는지 평가한다.
- 이 기준은 제품의 시각 품질 판단이다. 이미지의 실제 촬영 여부를 판별하는
  과학적 감식 기준이나 AI 생성 확률로 표현하지 않는다.

## 4. 판정 방법

| 판정 | 기준 |
| --- | --- |
| 합격 | 실제 이미지를 확인했고, 의도한 사진 스타일에서 자연스러움을 충족하며 적용되는 필수 조건도 충족한다. |
| 불합격 | 합성감·인공적인 장면 인상이 목표를 해치거나, 필수 기획·정체성·연속성 조건이 깨졌다. |
| 보류 | 필요한 원본, 참조, 비교 자료 또는 확인 가능한 해상도가 부족해 판단할 수 없다. 합격으로 계산하지 않는다. |
| 미평가 | 이미지가 없거나 실제 이미지를 확인하지 않았다. 프롬프트만 보고 이미지 품질을 추정하지 않는다. |

- 네 항목의 결과를 따로 기록한다. 자연스러움 불합격을 다른 항목의 우수함이나 평균 점수로 상쇄하지 않는다.
- 이전보다 나아졌다는 것과 합격했다는 것을 구분한다.
- 작은 흠을 과장해 실패를 만들어 내지도, 전체적인 인공성을 작은 흠으로 축소하지도 않는다.
- 심미적 판단에 근거 없는 숫자·정밀 점수·성공률을 붙이지 않는다.
- 운영자의 품질 피드백은 평가 기준을 보정하는 근거다. 기존 평가와 다르면
  기존 판정과 이유를 정정하고, 이전의 낮은 기준으로 결과를 방어하지 않는다.

## 5. 레퍼런스와 연속성 평가

### 정체성과 원본의 부수적 표현을 구분한다

레퍼런스의 역할은 선택된 범위로 판단한다. 정체성 보존이 원본의 표정, 의상,
포즈, 조명, 피부에 얹힌 색, 배경까지 그대로 유지한다는 뜻은 아니다.
다른 속성도 해당 게시물에서 명시적으로 선택됐다면 보존 대상이 될 수 있다.

- 얼굴·체형 레퍼런스가 있는데 외형을 장문으로 다시 묘사해야 한다고 전제하지 않는다.
  중요한 식별 특징과 필요한 변경은 남기되 중복 묘사를 평가한다.
- 원본의 보정·조명·포즈가 출력에 이어지는 듯해도 관찰과 원인 확정을 구분한다.
- 레퍼런스가 없는 결과가 더 자연스럽다는 비교만으로 레퍼런스가 원인이라고 확정하지 않는다.
  정체성 제약, 생성 경로, 입력과 설정이 함께 달라졌는지 확인한다.
- 반복적인 레퍼런스 색보정이나 매번 새로운 레퍼런스 제작을 기본 해결책으로 삼지 않는다.

### 필요한 컷 사이에서만 동일성을 요구한다

같은 게시물이라는 이유로 모든 컷의 의상·공간·조명·구도를 고정하지 않는다.
실제로 이어지는 대상과 상태를 기준으로 공유 범위를 판단한다.

- 반드시 같아야 할 요소, 달라져도 되는 요소, 의도적으로 바뀌는 요소를 구분한다.
- 공유 요소가 텍스트로만 정해졌는지, 실제 시각 자료가 입력됐는지 확인한다.
- 독립적인 생성 요청은 이전 결과를 보지 못할 수 있다. “같은”이라는 문구만으로
  시각적 동일성이 확보됐다고 평가하지 않는다.
- 기존 참조로 충분하면 불필요한 의존성을 만들지 않는다. 새로 생성된 외형을
  이어가야 할 때만 해당 결과를 필요한 컷의 근거로 공유하는 방식을 검토한다.
- 하나의 기준 컷에서 분기하거나 직전 컷을 잇는 방식 중 어느 하나도 모든 게시물의 기본 규칙으로 확정하지 않는다.
- 동일성을 유지하면서 구도·표정·행동까지 불필요하게 복제되는지도 함께 평가한다.

## 6. 이미지 프롬프트 평가와의 관계

프롬프트 준수와 실제 이미지 품질은 따로 검증한다.
프롬프트가 길다는 사실은 이미지가 부자연스러운 원인의 증거가 아니며,
짧아졌다는 사실도 품질 개선의 증거가 아니다.

| 정보 종류 | 평가 원칙 |
| --- | --- |
| 화면에 필요한 피사체·행동·상태·배치 | 필요한 시각 의미가 구체적으로 전달되는지 확인한다. |
| 정체성·참조 역할·시점·필수 연속성 | 직접 보이는 물체 이름이 아니어도 생성에 필요하므로 보존한다. |
| 감정·매체·분위기 | 결과에 의미 있는 차이를 만드는 만큼 유지한다. 무조건 삭제하지 않는다. |
| 게시 이유·과거 사건·행동의 사연 | 이번 화면에 필요한 상태와 구분한다. 기획 설명을 그대로 렌더링 지시로 옮기지 않는다. |
| 같은 내용을 반복하는 상태·외형 설명 | 필요한 의미를 보존하면서 통합한다. 입력 필드마다 한 문장씩 전사하지 않는다. |
| 다른 장면에만 적용되는 제한 | 적용 범위를 확인한다. 특정 상황의 제외 조건을 전체 이미지의 금지로 확대하지 않는다. |

확인할 질문:

1. 이 문장이 빠지면 의도한 이미지의 무엇이 달라지는가?
2. 그 차이는 이번 이미지에 필요한가, 이미 다른 문장에 표현돼 있는가?
3. 현재 보이는 상태와 그 상태에 이른 이유가 섞여 있지 않은가?
4. 기획의 과거·현재·미정 정보를 최종 프롬프트가 임의로 확정하지 않았는가?
5. 참조로 충분한 정보를 다시 열거하면서 불필요한 해석을 추가하지 않았는가?

최종 프롬프트에 불필요한 설명이 보이면 바로 금지 문장을 추가하지 않는다.
상위 기획 출력, 단계별 입력, 최종 작성 결과를 따라가며 어디에서 유입됐는지 확인한다.
이미 관련 지침이 존재한다면 지침 부재와 모델의 준수 실패를 구분한다.
작성 원칙의 상세 내용은 [이미지 프롬프트 작성 원칙](image-prompt-writing.md)을 따른다.

## 7. 결과 평가와 원인 분석을 분리한다

리뷰에는 다음을 구분해서 기록한다.

| 구분 | 기록할 내용 |
| --- | --- |
| 관찰 | 실제 이미지의 어느 부분에서 어떤 어색함이 보이는가? 전체 인상이라면 그 사실을 명시한다. |
| 품질 판단 | 그 관찰이 자연스러움 또는 필수 조건을 얼마나 해치는가? |
| 원인 가설 | 캐릭터 데이터, 기획, 최종 프롬프트, 참조, 모델, 실행 경로 중 무엇이 영향을 줬을 수 있는가? |
| 확인된 원인 | 실제 입출력이나 조건을 통제한 비교로 무엇까지 확인했는가? |
| 미확인 사항 | 무엇을 더 확인해야 원인을 좁힐 수 있는가? |

- 피부색·조명, 프롬프트 길이, 특정 레퍼런스 등 하나의 설명에 모든 문제를 맞추지 않는다.
- 캐릭터 설정의 부족, Agent의 판단 문제, 입력 전달·생성 구조의 문제를 구분한다.
- 저장된 설정뿐 아니라 실제 모델에 전달된 프롬프트·참조·설정을 확인한다.
- 텍스트 지침을 구현하거나 테스트가 통과했다는 사실로 실제 이미지 개선을 주장하지 않는다.
- 생성 실패는 자연스러움 평가가 아니다. 상세 오류가 없으면 콘텐츠·정책·형식 중
  어느 원인인지 추측으로 확정하지 않는다.
- 이미지를 고치기 위한 프롬프트 추가와 문제를 이해하기 위한 실험을 구분한다.
  원인이 미확정인 상태에서 제약을 계속 쌓지 않는다.

## 8. 평가·비교 절차

1. **이미지부터 확인한다.** 기획의 설명에 설득되지 않도록 일반적인 게시 크기에서
   전체 인상을 보고, 필요하면 원본에서 의심되는 부분을 확인한다.
2. **의도와 참조를 대조한다.** 기획·스타일 준수, 정체성, 연속성을 따로 평가한다.
   필요한 경우 실제 사진과 비교하되 비교 조건과 자료의 한계를 기록한다.
3. **실행을 확인한다.** 실제 전달된 입력과 결과가 저장된 계획에 맞는지 확인한다.
4. **원인 가설을 좁힌다.** 결과에서 직접 확인한 사실과 아직 검증되지 않은 설명을 나눈다.
5. **필요한 비교만 수행한다.** 주된 변경 요인을 분리하고 나머지 조건을 가능한 한 유지한다.
   생성의 변동성이 있으므로 조건별 한 장의 결과는 탐색 근거로만 취급한다.
6. **범용성을 확인한다.** 서로 다른 대상·촬영·조명·컷 구성에서도 개선과 회귀를 확인한다.
   성공한 결과만 골라 전체 개선이라고 보고하지 않는다.

비교 실험의 범위·횟수·비용은 해당 작업에서 정한다. 이 문서가 추가 생성 호출을
자동으로 허용하거나 모든 평가에서 대규모 실험을 요구하는 것은 아니다.

## 9. 기본 해결책으로 사용하지 않을 것

- 땀, 홍조, 모공, 노이즈, 흔들림, 흐트러진 머리, 비대칭을 자연스러움의 필수 조건으로 추가하기
- “사실적으로”, “자연스럽게”, “AI처럼 보이지 않게” 같은 품질 수식어를 계속 늘리기
- 특정 실패 장면을 막기 위해 촬영 방식·장비·사물·포즈를 통째로 금지하기
- 모든 사진을 무심한 표정, 우연한 순간, 어수선한 배경으로 통일하기
- 신체 부위를 반복 묘사하거나 숫자·광학 수치로 빈칸을 채우기
- 모든 컷에 동일한 조명·배경·구도 또는 이전 이미지 참조를 강제하기
- 자연스러움을 위해 캐릭터 정체성이나 의도된 매력을 포기하기

위 요소가 장면이나 스타일에 실제로 필요하면 사용할 수 있다.
금지 목록을 만드는 것이 아니라, 검증 없이 만능 처방으로 사용하는 것을 피한다.

## 10. 리뷰 기록 양식

```text
평가 대상 / 확인 시점:
실제 확인한 이미지·참조·비교 자료:
전체 판정: 합격 / 불합격 / 보류 / 미평가

자연스러움:
기획·스타일 준수:
정체성 유지: 해당 없으면 명시
컷 사이 연속성: 해당 없으면 명시

관찰된 어색함과 위치:
전체적인 인공성이 있다면 그 인상:
확인된 사실:
원인 가설과 근거:
확인하지 못한 사항:

개선 대상: 캐릭터 데이터 / Agent 프롬프트 / 워크플로우 / 참조·모델 검증
```

평가 기록은 관찰과 판단을 남기기 위한 것이다. 이 양식을 생성 프롬프트에 그대로 주입하지 않는다.
