# 이미지 프롬프트 최적화 실험 보고서

- 실험 대상: OPOD 게시물 기획 Agent, 이미지 프롬프트 Agent, 생성 이미지 평가 Agent
- 주 캐릭터: 서린
- 기준 게시물: `019febb5-c5fc-702c-8f5b-d6579285de12`
- 실험 브랜치: `experiment/image-prompt-optimization`
- 실험 종료 조건: LLM 또는 fal.ai의 명시적 크레딧·결제 한도 오류
- 종료 사유: fal.ai `403 {"detail":"User is locked. Reason: TOP_UP."}`
- 최종 확인된 fal.ai 당일 지출: `$4.00`

## 결론

프롬프트 평가는 기준 약 5점에서 최종 5.0/5, 이슈 0건까지 개선됐다. 생성 이미지도 후반 실험에서 사진성·의상·정체성·손과 기기 분리 항목은 대부분 4점 수준까지 올라갔다. 남은 주요 실패 원인은 이미지 자체의 저품질보다, 얼굴 비식별 조건을 지나치게 넓게 해석해 목·머리카락까지 제외하도록 만든 크롭 계약이었다.

이를 `얼굴과 턱만 프레임 밖, 목·어깨·식별 불가능한 머리카락은 허용`하는 최소 프라이버시 크롭으로 수정했다. I10의 재생성 프롬프트는 모든 평가 항목 5점으로 통과했지만, 실제 이미지 생성은 fal.ai 요청 두 건이 각각 세 번의 300초 폴링 타임아웃을 거친 뒤 실패했다. 새 요청으로 공급자 상태를 확인하자 `TOP_UP` 계정 잠금이 명시적으로 반환되어 실험을 종료했다.

현재 승자 규칙은 다음과 같다.

1. 장면의 의상·배경과 직접 일치하는 깨끗한 레퍼런스를 첫 번째 앵커로 보낸다.
2. 레퍼런스 편집 프롬프트는 레퍼런스의 정체성만 보존하고, 레퍼런스 속 휴대폰·포즈·배경을 복제하지 않는다.
3. 최종 장면에 보이지 않는 휴대폰은 외형·색상·손잡이 방식까지 묘사하지 않는다.
4. 양손이 비어야 하면 고정 셀프타이머 촬영을 사용하고 휴대폰과 조작 손을 프레임 밖에 둔다.
5. 크롭은 제외 대상만 나열하지 않고 상단·하단의 보이는 랜드마크를 함께 고정한다.
6. 얼굴 비식별이 목적이면 얼굴과 턱만 제외하고, 목·어깨·식별 불가능한 머리카락은 허용한다.
7. 장면에 명시되지 않은 나이, 국적, 피부색, 체형, 가슴 크기, 과장된 머리색을 최종 프롬프트에 추가하지 않는다.

## I9 이미지 분석

I9는 후반 개선의 방향을 결정한 회차다.

- 컷 1 후보 1: 크림 셋업, 나무 바닥의 베이지 복도, 자연스러운 전신 구도가 일관됐다.
- 컷 2 후보 1: 같은 복도·조명·의상을 유지했고 빈손과 기기 제거도 성공했다.
- 사진성, 아티팩트, 의상, 정체성은 대체로 4점 수준이었다.
- 자동 검수의 최종 거절 사유는 계획이 목과 머리카락까지 보이지 않도록 요구했는데 결과에 목과 머리카락이 남았다는 점이었다.

이 결과는 모델이 프롬프트를 전반적으로 못 따른 것이 아니라, 기획의 프라이버시 계약이 실제 소셜 피드 이미지에 비해 과도했다는 뜻이다. 따라서 모델 품질을 더 압박하기보다 기획·평가 기준을 `얼굴과 턱 제외`로 좁히는 것이 맞다.

## I10 사전 평가와 종료 상황

I10 기획은 같은 베이지·크림 현관과 크림 셋업, 고정 셀프타이머, 빈손, 얼굴·턱 제외를 명시했다. 실제 레퍼런스 순서도 개선 의도대로 동작했다.

- 컷 1: 깨끗한 크림 앵커 `019ff2cb-826c-763c-9707-121d82957ec5`가 첫 번째
- 컷 2: 같은 깨끗한 앵커만 사용
- 프롬프트 1차: `curvy-slim`, `jet-black` 같은 임의 외모 표현 때문에 2.99
- `8c75a5d` 배포 후 2차: 두 컷 모두 5.0, 교차 일관성 5.0, 이슈 0건

I10 기획 평가는 3.99였다. 남은 지적은 두 컷의 시각적 사건이 비슷하다는 점, 캡션의 비교 표현이 모호하다는 점, 최근 게시물 정보 부족이었다. 레퍼런스 지적 중 일부는 실제 선택 결과와 맞지 않았으므로 평가 Agent가 실제 `referenceMediaIds`를 우선 확인하도록 후속 보강할 가치가 있다.

이미지 생성 단계에서는 최초 두 요청이 각각 300초 폴링 타임아웃을 세 번 반복했다. 재시도 중에는 동일 provider request ID를 유지해 중복 제출을 막았다. fal.ai 공식 상태 페이지는 당시 `All systems operational`이었고 공개 장애는 없었다. 실패 초안을 공식 집계 로직으로 전환한 뒤 단일 컷을 새 요청으로 확인하자 즉시 다음 오류가 반환됐다.

```text
fal result failed (403): {"detail":"User is locked. Reason: TOP_UP."}
```

이 오류를 사용자 지정 종료 조건인 fal.ai 크레딧 소진으로 판정했다. 추가 과금을 막기 위해 생성 워커 자동 루프는 다시 껐고, 평가 워커는 기존 설정대로 유지했다.

## 레퍼런스 운영 결과

- 최종 활성 레퍼런스 수: 12장
- 권장 첫 앵커: `019ff2cb-826c-763c-9707-121d82957ec5`
- 특성: 휴대폰 없음, 팔을 내린 자연스러운 자세, 크림·베이지 의상과 배경
- 휴대폰이 포함된 이전 레퍼런스는 분석 전용으로 표시하고 생성 입력에서는 사용하지 않도록 했다.
- I9의 우수 후보를 시각 프로필에 추가하려 했으나 저장 후 활성 개수가 유지돼 승격이 확정되지 않았다. 보고서에서는 승격된 것으로 간주하지 않는다.

## 충전 후 재개 순서

1. fal.ai 충전 후 연결 테스트로 403 잠금 해제를 확인한다.
2. 생성 워커는 계속 끈 상태에서 I10 컷 1만 새 요청으로 실행한다.
3. 완료되면 컷 2를 실행해 동시에 두 요청을 보내는 변수를 제거한다.
4. 이미지 평가를 실행해 최소 프라이버시 크롭의 실제 통과 여부를 확인한다.
5. 통과하면 같은 규칙을 한소이에 교차 검증한다.
6. 서린·한소이 모두 통과한 뒤에만 Agent 프롬프트를 기본 브랜치 후보로 승격한다.
7. 다음 개선에서는 기획 Agent의 컷 간 사건 다양성, 캡션 명료성, 평가 Agent의 실제 레퍼런스 ID 검증을 우선한다.

생성 이미지 크기 고정 문제는 사용자 요청대로 이번 분석과 변경 범위에서 제외했다.
