## 목적과 근거

사진과 기획의 사실을 유지하면서 캐릭터가 직접 공유할 법한 글을 만든다.
2026-09-27 사용자가 OPOD 게시물 생성 스킬의 반복된 캡션 문제를 제품 Agent에
적용하도록 요청했다. 스킬의 7~8단계와 `production-state.md`의 캡션 계약,
아래 작업 브리프에서 확인된 패턴을 반영했다.

| 확인된 문제 | 근거 | 적용한 원칙 |
| --- | --- | --- |

스킬은 수동 제작 워크플로우다. 그 승인 단계나 외부 소셜 조사 절차를 제품의
자동 생성에 그대로 추가하지 않았다. 특정 캐릭터의 승인 문장·하트 개수·어미를
공통 프롬프트에 예시로 심지 않는다. 짧은 반말·한국어를 전역 기본값으로
강제하지 않으며, 긴 글이나 서정적인 말투가 설정된 캐릭터는 그 설정을 따른다.

2026-09-27 사용자 추가 결정: 개선은 알려진 캐릭터·사례에 국한되지 않아야 한다.
따라서 특정 표현의 금지 목록보다 다음 입력 역할을 적용한다. 기획은 사건의
사실을, 게시 목적은 말할 내용의 선택을, 캐릭터의 게시 말투는 표현 방식을
결정한다. 최근 글은 약한 문체 근거와 반복 확인 자료다. 설명·농담·성찰·질문·
광고 표현 자체를 금지하지 않고, 이번 목적이나 주어진 문체에 필요한지 판단한다.
과거 승인 캡션은 품질 문제를 설명하는 사례이며 새로운 출력의 정답이 아니다.

## 구현과 범위

- 기존 owner `prompts/caption-writer.ts`의 `caption-writer-v3`에 작성 원칙을
  반영했다. `CaptionWriterAgent`와 runner의 실제 호출 경로를 확인해 기존
  owner를 확장했다. 별도 캡션 평가 Agent·후보 생성·자동 재시도는 추가하지 않았다.
- 사실은 기존 `postPlan.intent`와 사진/이미지 계획의 교집합 규칙을 유지한다.
  장비, 생성된 표지판, 시각적 장소 레퍼런스로 실제 방문·운동 성과를 추론하지 않는다.
  최근 글의 사건을 이번 사건으로 복사하지 않는다.
- `caption-set-v2`는 이모지처럼 언어 텍스트가 없는 캡션에서
  `captionLanguages: []`를 허용한다. 이전에는 프롬프트가 이모지를 언어에서
  제외하면서 schema/parser가 언어 최소 1개를 요구했다. 새 스키마와 파서를
  함께 수정했고, 기존 언어 태그가 있는 결과도 그대로 읽는다. 본문 공백은
  여전히 거부하고 해시태그는 기존대로 0~5개다.
- 언어의 의미적 분류는 기존처럼 모델이 담당한다. 파서는 태그 형식·중복·개수와
  본문 형식을 검사하며 문체나 사실 일치를 자동 판정하지 않는다.
- 최근 게시물 입력은 기존 그대로다. 모든 과거 글을 사용자가 승인한 모범 답안으로
  간주하지 않으며, 반복을 피하려고 새 사실이나 낯선 표현을 만들지 않는다.
- 삭제·정정 규칙은 현재 `operatorRequest`/`operatorNote`에 전달된 범위에
  적용된다. 과거 대화·거절 이력을 자동으로 수집하거나 누적 저장하는 기능은
  이번에 추가하지 않았다. 관리자 직접 문자열 편집 경로도 변경하지 않았다.
- 스킬 파일, 캐릭터 설정, DB, 개발서버는 변경하지 않았다. 개발서버의 콘텐츠
  프로필 이전·분리 배포는 여전히 별도 작업이다.

## 검증과 품질 비교 기준

자동 회귀는 `caption-writer.spec.ts`와 `post-pipeline-v3.runner.spec.ts`가
담당한다. 이모지 단독/태그 없음 결과의 수락, 실제 LLM 요청 schema의 빈 언어
배열 허용, 결과의 보존과 게시 대기 전이, 기존 텍스트 결과 호환을 확인한다.
빈 본문·잘못된 언어 태그·중복 태그 거부와 이미지 전달도 기존 검사를 유지한다.
모의 LLM 응답 테스트를 자연스러움 개선의 증거로 취급하지 않는다.

실제 모델 비교에서는 동일한 사진·기획·캐릭터 입력으로 v2/v3 결과를 비교한다.
다음은 평가 기준이며 이번 변경에서 실모델 비교를 실행한 결과가 아니다.

| 사례 | 통과 기준 | 실패 기준 |
| --- | --- | --- |
| 운동 직후의 체감, 구체적 측정 기록 없음 | 입력에 있는 행동·체감만 표현 | 임의 시간·중량·최고기록, 추상적인 선수 선언 |
| 여러 장소가 보이는 일상 캐러셀 | 캐릭터에게 중요한 일부 내용만으로 완결 가능 | 모든 사진 설명, 동선 요약, 의무적인 교훈 |
| 짧은 근황과 참여 유도 요청 없음 | 짧게 끝나도 됨 | 팔로워 질문이나 광고 문구 자동 추가 |
| 비슷한 주제의 최근 글이 있음 | 말투는 유지하고 특징적인 문장 틀 재사용 회피 | 명사만 바꾼 기존 캡션, 새로움을 위한 사실 날조 |
| 명시적으로 긴 기록체를 쓰는 캐릭터 | 설정된 길이·어미·감정 강도 유지 | 모든 캐릭터가 같은 짧은 반말로 수렴 |
| 이모지 단독·해시태그 없음 요청 | 해당 결과와 빈 언어 배열 유지 | 문장·언어·해시태그를 억지로 채움 |
| 확정 문구와 일부 요소 삭제 지시 | 전달된 문구·줄바꿈 유지, 해당 요소만 수정 | 표현을 미화하거나 지운 요소를 다시 추가 |

범용성은 위 과거 사례의 재현만으로 확인하지 않는다. 별도의 합성 캐릭터로
다음 조합도 비교해야 한다. 실제 캐릭터의 비공개 데이터를 복제할 필요는 없다.

- 같은 장면·사실에 서로 다른 게시 말투: 간결한 기록체와 자세한 서정체가
  같은 문장 틀로 수렴하지 않아야 한다.
- 같은 캐릭터에 서로 다른 게시 목적: 가벼운 근황과 상세한 작업 설명에서
  말투는 이어지되 분량과 설명 수준이 목적에 맞게 달라져야 한다.
- 유머·질문·홍보가 명시적으로 적합한 상황: 과거 실패 유형이라는 이유만으로
  필요한 표현을 제거하지 않아야 한다.
- 다른 언어·높임말·혼합 언어: 한국어 짧은 반말로 강제되지 않아야 한다.
- 이력이 없는 새 캐릭터: 최근 글이 없어도 명시된 말투와 사건으로 작성하고,
  임의 유행어·습관·과거 사건을 만들어 빈칸을 채우지 않아야 한다.

문장별 정확한 정답 문자열이나 자동 미학 점수를 두지 않는다. 기존보다 캐릭터
목소리가 유지되는지, 근거 없는 내용과 반복적인 표현이 줄었는지 직접 비교한다.
