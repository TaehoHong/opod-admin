# 이미지 프롬프트 작성 원칙

2026-09-27 적용. 사용자가 관찰한 과도한 세부 지시와 인위적인 결과를 줄이되,
캐릭터 정체성·기획 구도·명시된 스타일·필수 제외 조건을 보존한다.
프롬프트 길이와 이미지 품질의 인과관계를 입증한 실험 결과는 아니다.

## 조사 근거와 적용 판단

- [Google Gemini 이미지 가이드](https://developers.googleblog.com/how-to-prompt-gemini-2-5-flash-image-generation-for-the-best-results/):
  분리된 키워드 나열보다 연결된 장면 설명을 권장한다. 수정에서는 변경할
  요소와 유지할 요소를 명확히 구분한다.
- [Google DeepMind 프롬프트 가이드](https://deepmind.google/models/gemini-image/prompt-guide/):
  짧은 프롬프트로 시작할 수 있으며 세부사항을 점진적으로 추가할 수 있다.
  원하는 결과를 통제하는 구체적인 지시도 유효하므로, 무조건 짧게 자르지는 않는다.
- [Gemini API 이미지 가이드](https://ai.google.dev/gemini-api/docs/image-generation):
  제외할 항목의 나열보다 원하는 장면을 설명하는 방식과 작은 단위의 반복 수정을 권장한다.
- [BFL 프롬프트 구성 가이드](https://docs.bfl.ai/guides/prompting_unified_building):
  짧게 시작하고 이미지에 영향을 주는 정보만 추가하며, 모든 구성 항목을 채울
  필요는 없다고 설명한다. 효과와 일반적인 품질 수식어의 중첩을 피한다.
  이 문서의 길이 예시는 FLUX.2 기준이다. Kontext의 검증된 최적 길이로
  해석하거나 OPOD의 공통 단어 수 제한으로 적용하지 않는다.
- [BFL Kontext 이미지 편집 가이드](https://docs.bfl.ai/kontext/kontext_image_editing):
  간단한 변경 지시와 반복 편집 사례를 제공한다. 기존 OPOD의 모델 선택이나
  레퍼런스 슬롯 계약을 바꾸는 근거로 사용하지 않는다.

## 작성 계약

1. 주체·행동 또는 상태, 장소, 필요한 구도를 연결된 문장으로 설명한다.
2. 정체성·의상·공간·레퍼런스 역할은 유지한다. 같은 내용을 한 컷 안에서
   여러 표현으로 반복하지 않는다. 각 컷은 독립 실행되므로 필요한 공통 조건은
   다른 컷에도 다시 쓴다.
3. 기획과 작성된 스타일에 없는 피부 결·모공·광학 수치·조명 효과·노이즈·
   비대칭·미세 결함을 현실감 표현이라는 이유로 추가하지 않는다.
   명시된 필름 질감이나 운동 흔적까지 삭제하는 규칙은 아니다.
4. 일반적인 품질 수식어와 AI 흔적 방지 체크리스트를 생성 프롬프트에 추가하지 않는다.
5. 제외 조건은 의미가 정확히 같을 때 원하는 결과로 표현한다. 예를 들어
   로고 제외는 무지 의상으로 표현할 수 있다. 정확히 대체할 수 없으면 짧은
   제외 문장을 유지한다. 필수 조건을 길이 제한 때문에 버리지 않는다.
6. 관련 없는 정보와 중복 표현을 줄인다. 고정 단어 수, 정규식 기반 의미 삭제,
   잘라내기, 추가 LLM 정리 호출은 도입하지 않는다.

예시(합성 기획을 설명하는 예시이며 실제 LLM 출력이나 특정 캐릭터 설정이 아님):

> A cup of coffee on a cafe table, viewed from above. Only the cup and tabletop
> are in frame. The cup is unbranded.

이 기획에 없는 85mm 렌즈, 황금빛 조명, 초고해상도 질감, 필름 노이즈나 손을
자연스러움을 이유로 추가하지 않는다.

## 코드 소유권과 호환성

- `prompts/image-prompt-generator.ts`가 공통 작성 원칙을 소유한다.
  `image-prompt-generator-v6`로 갱신했다. 핵심 주체와 크롭을 먼저 표현하고,
  레퍼런스 정체성의 장문 재묘사를 피한다. 반환 전에 수량·위치·접촉·문구·
  구도·필수 조건 보존을 같은 응답 안에서 확인하도록 지시한다.
- `src/worker/image-model-policy.ts`의 `buildPromptGenerationInput`이 LLM용
  입력 축약을 소유한다(`owner-found`: 기존 package 구성 owner 확장).
  원본 package는 artifact·출력 검증·실행 추적에 보존하며, LLM에는 시각적
  결정과 슬롯 역할만 전달한다. 중복 referenceBindings, 내부 ID, 기획 목적,
  장소 ID와 system에 이미 주입된 모델 정책을 user 입력에서 제외한다.
  모든 컷이 인물 비노출이면 appearance도 비우되 스타일·제외 조건은 유지한다.
  혼합 캐러셀과 이전 기획의 선택 필드는 그대로 전달한다.
- `prompts/image-model-policies.ts`는 모델별 표현·슬롯 문법을 소유한다.
  Nano 정책 v3, Kontext 정책 v2를 사용한다. 모델·한도·출력 스키마는 그대로다.
- `PostPipelineV3Runner`는 이미 조회한 장소 중 선택된 장소의 제외 조건을
  `imagePlanning.locationExclusions`에 보존하고, 캐릭터 제외 조건과 함께
  `PromptBuildPackage.subjectContract.exclusions`로 전달한다.
  새 DB 조회나 Repository 의존을 추가하지 않는다.
- 제외 조건이 모두 입력된 작업은 `_v3.exclusionsResolved: true`를 저장한다.
  `GenerationWorkerService`는 이 작업에 현재 캐릭터·장소 원문을 다시 붙이지 않는다.
  모델 정책이 사용하는 별도 `negativePrompt` 출력은 계속 전달한다.
- 이전 장소 기획에 snapshot이 없으면 기존 제외 조건 결합을 유지한다.
  해당 초안은 이미지 기획부터 다시 실행해야 새 경로를 사용한다. 장소 없는
  초안은 장소 제외 조건이 필요 없으므로 새 경로를 사용할 수 있다.
- 기존 owner를 확장했다(`owner-found`). 새 테이블, 모델 교체, 스타일 전달 구조,
  컷별 모델 선택, 레퍼런스 검증 확대는 이번 변경에 포함하지 않는다.

## 검증 범위

회귀 테스트는 선택 장소 조건의 전달, 다른 장소 조건 제외, 새 작업에서 원문
재첨부 방지, 별도 negativePrompt 보존, 이전 초안 호환을 검증한다.
지침 문구 포함 여부만 확인하는 테스트는 추가하지 않는다.

실제 LLM이 간결하게 작성하는지와 이미지가 더 자연스러워지는지는 별도 평가 대상이다.
같은 기획·레퍼런스·모델 설정으로 이전/신규 프롬프트를 비교하고, 짧아진 정도보다
필수 조건 보존·임의 연출 추가·정체성·최종 이미지의 자연스러움을 함께 확인한다.
이번 변경에서 실제 모델 호출이나 이미지 A/B 평가는 수행하지 않았다.

v6 로컬 검증: 단위 테스트 50 suites / 473 tests, E2E 10 suites / 36 tests,
lint, build, 변경 코드의 Prettier 검사와 diff 검사를 통과했다. 입력 축약 전
실패하던 2개 회귀 테스트가 통과하며 혼합 캐러셀·이전 기획 호환도 확인했다.
HTTP 테스트는 로컬 포트가 허용된 실행 환경에서 실행했다. 이 검증은 입력의
정보 보존과 실행 호환에 대한 것이며, 생성 모델의 의미 보존 확인 수행 여부나
최종 이미지의 품질을 증명하지 않는다.

## 2026-09-28 공통 기획·작성 지침 수정

`image-planner-v7`은 다음을 적용한다. 캐릭터 이름·특정 운동·특정 SNS 구도에
따른 분기는 없다.

- 인물이 있어도 필요한 시각 상태가 없으면 `subjectState`를 비울 수 있다.
  `motionEvidence`도 장면에 이미 표현된 동작을 반복하거나 효과를 만들기 위해
  채우지 않는다. 기존 출력 schema는 이미 빈 문자열을 허용하므로 변경하지 않았다.
- 각 컷의 `visualPurpose`는 게시물에 포함되는 이유이며 서로 다른 사건이나
  정보를 반드시 뜻하지 않는다. 같은 순간의 작은 자세·표정 변화도 허용한다.
- `notInFrame`은 명시된 입력 제약이나 촬영 구조에 필요한 제외만 담는다.
  언급되지 않은 배경 사물을 임의로 금지하지 않는다.
- 공유 의상·소품·환경의 시각 근거로 선택한 레퍼런스는 그 요소가 보이는
  해당 컷들에 같은 보존 범위로 배정하도록 지시한다. 얼굴 레퍼런스만으로
  의상 디자인이 정해지거나 앞 컷 결과가 다음 독립 호출에 보인다고 가정하지 않는다.
  레퍼런스 선택은 계속 이미지 기획 Agent가 수행하며 코드가 임의로 추가하지 않는다.

`image-prompt-generator-v7`은 scene/visibleParts/상태/공유 요소를 별도 문단으로
전사하지 않고 중복된 사실을 한 번만 표현하도록 명확히 한다. visibleParts는
구도·노출 범위를 확인하는 조건으로 사용한다. 각 컷에는 독립 실행에 필요한
구체적인 공통 내용을 쓰고, 입력되지 않은 이전 결과를 “같은”이라는 말로 참조하지 않는다.

초안 생성 추적은 `DraftsService`가 fal/OpenAI provider 이름에서 실제 모델을
읽어 기획 모델과 비교한다. 경로와 레퍼런스 비교도 계속 적용한다.
`drafts.service.spec.ts`는 OpenAI 정상 일치, fal 호환, 다른 모델·다른
레퍼런스·다른 경로의 불일치를 확인한다.

이 변경은 지시·실행 추적의 수정이다. 프롬프트 문구 포함 여부만 검사하는
테스트를 만들지 않으며, 기존 parser/runner 테스트로 계약 호환을 확인한다.
시각 품질이나 공유 의상 보존의 실제 개선은 생성 비교로 별도 검증해야 한다.
새로운 검수 Agent, 모델 품질 변경, 캐릭터별 데이터 작성·이전은 포함하지 않는다.

v7 검증: OpenAI 정상 모델이 불일치로 표시되는 회귀를 재현한 뒤 수정했다.
관련 5 suites / 68 tests, 전체 단위 52 suites / 507 tests,
생성 API E2E 1 suite / 7 tests, lint/build/format/diff 검사를 통과했다.
전체 단위 첫 실행의 HTTP 포트 제한은 포트 접근이 허용된 환경에서 동일 명령을
재실행해 통과했다. 실제 모델 생성 비교 및 개발 서버 배포는 수행하지 않았다.
