## 2. 사용자가 명시한 제작 지시

### 2.1 전체 사진의 자연스러움

- 사람이 실제로 촬영한 사진처럼 자연스러워야 한다.
- 질감, 구도, 신체 비율과 원근감을 함께 검토한다.
- 모든 사진에 전신을 억지로 담지 않는다. 행동과 촬영 거리상 자연스러운 부분 구도를 허용한다.
- 고정된 OPOD 필터를 사용하지 않고 장면에 맞는 필터와 색보정을 선택한다.
- 강한 아웃포커싱을 적용하되 주 피사체와 상황은 읽혀야 한다.
- 장면에 맞는 카메라 높이, 렌즈 거리, 셔터 표현과 촬영 방향을 사용한다.
- 운동 장면에는 움직임과 힘을 쓰는 순간이 보여야 한다.
- 얼굴 표정은 실제 운동 강도에 맞게 힘듦, 집중, 호흡과 긴장이 드러나야 한다.
- 권도건의 얼굴이 보이는 컷은 인물 레퍼런스와 얼굴이 일치해야 한다.
- 후보를 한꺼번에 승인하지 않고 사진마다 구도, 신체 비율, 원근감과 상황 현실성을 검수한다.

- 크로스핏 박스의 장비 배치와 장비 형태가 확실하지 않으면 별도로 실제 박스 레퍼런스를 조사한다.

### 2.3 운동 장면과 배경 인물

- 배경에 다른 운동 참가자들을 넣는다.
- 4번과 5번 후보는 다른 사람과 함께 운동하는 구도로 만든다.
- 배경 인물은 장식처럼 임의 배치하지 않고 실제 수업의 같은 동작, 대기 또는 이동 흐름에 맞게 둔다.
- 운동 중인 순간에는 지나치게 깨끗한 정지 사진 대신 순간적인 흐림, 흔들림, 힘이 실린 자세와 불완전한 크롭을 허용한다.
- 멀리서 줌인한 듯한 압축 원근과 관찰자형 촬영 구도를 사용할 수 있다.

### 2.4 로잉 장면

- 4번 후보는 더 멀리서 찍은 듯한 구도로 만든다.
- 오른쪽에 불필요하게 배치된 사람은 제거한다.
- 로잉 머신을 원형이나 둥근 대형으로 배치하지 않는다.
- 두 대만 외따로 둔 구성도 실제 단체 수업 공간으로 보기에 어색하므로 피한다.
- 실제 크로스핏 박스에서 볼 수 있는 여러 대의 로잉 머신을 평행한 열 또는 정렬된 스테이션으로 배치한다.
- 로잉 머신은 레퍼런스로 확인한 실제 기구의 레일, 시트, 플라이휠 하우징, 핸들과 발판 구조를 유지한다.
- 벽에 붙이는지 여부를 추측으로 고정하지 않고 해당 박스의 동선과 실제 레퍼런스를 근거로 결정한다.

- 다른 참가자와 함께 등장한다.
- 두 사람이 마주보고, 상대방은 말하는 중이며 권도건은 상대를 바라본다.
- 권도건의 얼굴이 식별되는 방향이어야 한다.
- 멀리서 줌인한 듯한 촬영 거리와 압축 원근을 사용한다.
- 땀이 많이 나 피부가 더 반짝이고 머리와 몸이 젖어 있어야 한다.

## 3. 사용자의 부정적 평가

### 3.1 이미지 전반

다음 특성이 사람의 실제 운동 사진이 아니라 AI 생성 이미지처럼 보인다고 평가했다.

- 질감, 구도와 원근감이 지나치게 정돈되거나 시각적으로 이상함
- 모든 장면에서 전신을 넣으려 해 관절, 체형과 화면 여백이 부자연스러움
- 얼굴이 권도건 레퍼런스와 다름
- 신체 비율이 이상함
- 운동 중인데 얼굴이 너무 평온함
- 순간 동작인데 피사체와 화면이 지나치게 깨끗하고 선명함
- 운동 사진인데 동작의 방향, 속도와 힘이 느껴지지 않음
- 배경 인물이 실제 수업 참여자가 아니라 장면을 채우기 위해 배치된 것처럼 보임
- 피사계 심도, 필터와 구도가 모든 컷에서 같은 AI 템플릿처럼 적용됨

### 3.2 로잉 장면

- 실제 크로스핏 박스의 기구 배치로 보이지 않음
- 로잉 머신 두 대만 놓여 있어 단체 수업 공간으로 부자연스러움
- 로잉 머신을 둥글게 배치해 실제 운동 동선과 맞지 않음
- 로잉 머신 자체의 형태가 실제 기구와 다름
- 사용자가 제거하라고 한 오른쪽 인물이 남거나 다른 요소가 함께 바뀜

이 평가는 단순히 `로잉 머신 수를 늘린다`는 지시가 아니다. 장비의 형태, 정렬 방향, 수업 동선, 배경 인원과 촬영 위치를 하나의 공간 계약으로 검수해야 한다.

### 3.3 운동 후 음료 장면

- 정면 중심 구도와 병 노출이 제품 광고처럼 보임
- 사진마다 전신을 담으려는 습관이 특히 이 장면을 어색하게 만듦
- 권도건이 상대를 보거나 대화에 참여하지 않아 사회적 맥락이 약함
- 음료를 들고만 있거나, 마시는 동작이 명확하지 않음
- 땀과 젖은 옷이 운동 직후의 강도에 비해 부족함
- 자연스러운 원거리 스냅이 아니라 AI가 인물과 제품을 중앙에 배열한 장면처럼 보임

### 3.4 캡션

초기 캡션 후보들은 실제 사람이 작성할 만한 글이 아니라고 평가했다. 특히 다음 패턴이 거절됐다.

- 일반적인 동기부여 문장을 크로스핏 말투처럼 포장함
- 사진마다 상황을 설명하거나 세 줄짜리 농담과 결론을 억지로 만듦
- `오늘 운동 요약`, `사진은 멀쩡해 보이네` 같은 익숙한 인터넷 문구에 의존함
- 실제 기록이 없는데 운동 시간, 중량, Rx와 성과를 지어낼 위험이 있음
- `오운완`, `#WOD`, `#크로스핏`과 해시태그를 넣는 것만으로 커뮤니티 말투라고 판단함
- `내부 표현`처럼 의미가 불분명한 용어로 문체를 설명함

사용자가 원한 것은 크로스핏 용어를 많이 쓰는 글이 아니라, 실제로 함께 운동한 사람이 짧게 올릴 법한 글이었다.

### 3.5 작업과 인증 처리

- 사용자 동의 없이 인증정보가 저장된 WebStorm 세션을 읽으려 한 행동
- 개발 Admin과 현재 브라우저 세션을 사용할 수 있는데 IDE 또는 DB 클라이언트의 인증 상태를 우회 경로로 탐색한 행동

이는 단순한 구현 실수가 아니라 인증 경계 위반이다. 이후 작업에서는 저장된 개발 도구 세션을 인증 수단으로 사용하지 않아야 한다.

- 실제 크로스핏 박스에서 수업 중 찍은 사진처럼 공간과 장비가 설명된다.
- 촬영자가 운동 동선 밖에서 망원으로 순간을 포착한 듯한 구도가 자연스럽다.
- 동작 중인 컷에는 운동 방향과 속도를 보여주는 자세, 표정, 땀과 적절한 움직임 흔적이 있다.
- 모든 사진이 전신일 필요가 없고, 행동에 맞는 부분 크롭과 가림이 있다.
- 강한 아웃포커싱이 적용되더라도 권도건의 얼굴과 핵심 동작은 식별된다.
- 배경의 다른 참가자들이 실제 수업 흐름 안에서 서로 다른 거리와 자세로 보인다.
- 로잉 머신은 실제 기구 형태와 평행한 수업 배치를 가진다.
- 운동 후 장면은 음료보다 두 사람의 대화와 피로가 먼저 읽힌다.
- 권도건은 상대방을 바라보며 마시고, 상대방은 말하는 순간으로 보인다.
- 땀에 젖은 피부, 머리, 상·하의가 운동 직후의 상태와 일치한다.
- 캡션은 사진을 해설하지 않고 그날의 감정과 함께한 사람에게 짧게 말한다.
- 최종 캡션처럼 두 문장과 이모지 하나, 해시태그 없음도 완성된 결과로 인정한다.

## 5. 피드백 해석 시 주의할 점

### 5.1 최종 이미지 선택 번호

사용자는 처음 `1,5,6 선택`이라고 했고, 움직임이 너무 깨끗한 사진의 보정 대상을 `2번`이라고 말했다가 곧 `아 3번`으로 정정했다.

최종 해석은 다음과 같다.

> 원래 후보 1, 3, 5, 6을 선택하고, 3번 후보의 순간 동작을 더 자연스럽게 보정한다.

`2번` 지시는 `superseded`로 보존하되 최종 선택이나 수정 대상에 적용하지 않는다.

### 5.2 `아웃포커싱 강하게`의 의미

강한 배경 흐림은 고정 필터 이름이나 모든 컷의 동일한 블러 값을 뜻하지 않는다. 주 피사체를 분리하면서도 크로스핏 박스, 장비와 다른 참가자의 존재는 읽혀야 한다. 운동과 대화 장면의 촬영 거리 및 렌즈에 맞게 심도를 결정한다.

### 5.3 `다른 사람도 넣어`의 의미

배경에 사람 수만 늘리는 요청이 아니다.

- 다른 사람은 같은 수업과 공간을 공유해야 한다.
- 각 인물은 전경·중경·배경 중 명확한 깊이에 있어야 한다.
- 주 피사체의 관절이나 장비를 가리지 않아야 한다.
- 6번에서는 단순 배경 인물이 아니라 권도건과 대화하는 상대방이다.
- 4번에서는 불필요한 오른쪽 인물 제거 지시가 이후의 일반적인 배경 인물 추가 지시보다 우선한다.

### 5.4 `로잉 머신은 벽에 붙어 있지 않나`의 의미

사용자도 확신하지 않는다고 명시했으므로 `벽에 붙인다`를 규칙으로 저장하면 안 된다. 확정된 요구는 실제 박스 레퍼런스를 조사하고 장비 형태, 정렬과 동선을 현실적으로 만드는 것이다.

### 5.5 음료 브랜드와 광고성

Powerade는 사용자가 요청한 소품이므로 삭제 대상이 아니다. 문제는 브랜드 자체가 아니라 정면 제품 중심 구도와 과도한 제품 가시성이다. 최종 규칙은 `음료를 실제로 마시는 사회적 순간을 우선하고 병을 영웅 소품으로 만들지 않는다`이다.

### 5.6 최종 캡션의 일반화 범위

`힘들었는데 재밌었다🔥 / 다들 고생하셨습니다!`는 권도건의 이번 게시물에 승인된 사례다. 모든 운동 게시물에 복제할 전역 템플릿은 아니다. 전역으로 일반화할 수 있는 것은 짧은 감정, 함께한 사람을 향한 말과 검증되지 않은 기록을 만들지 않는 원칙이다.

## 6. Skill에 추가하거나 강화할 규칙

### 6.1 콘텐츠 계약과 수정 잠금

운동 게시물은 컷마다 다음 필드를 잠근다.

- 동작 또는 운동 후 상태
- 카메라 위치, 높이, 거리와 렌즈 계열
- 전신·반신·부분 크롭
- 얼굴 가시성과 시선 대상
- 전경·중경·배경 인원과 상호작용
- 장비 종류, 수, 방향과 공간 동선
- 땀, 호흡, 젖은 머리와 옷 같은 신체 상태
- 모션 블러, 초점면과 피사계 심도
- 소품의 역할과 광고성 금지 여부

`6번만 다시`, `오른쪽 사람만 제거` 같은 요청은 언급된 필드와 그 필드에 직접 의존하는 요소만 변경한다.

### 6.2 레퍼런스 조사의 두 축

레퍼런스를 다음 두 축으로 분리한다.

1. 촬영 레퍼런스
   - 실제 CrossFit·HYROX SNS 사진
   - 촬영 거리, 렌즈 압축, 크롭, 흔들림, 초점 이탈과 배경 참가자
2. 도메인 구조 레퍼런스
   - 실제 크로스핏 박스와 제조사 장비 사진
   - 장비 해부 구조, 개수, 정렬, 벽과의 거리, 운동자 사이 간격과 통로

운동 장면에 특수 장비가 있으면 생성 전 `장비 형태`와 `공간 배치`를 별개 체크 항목으로 만든다. 사용자의 추측형 질문은 확정 사실로 변환하지 않는다.

### 6.3 이미지 검수 순서

각 이미지를 다음 순서로 한 장씩 검수한다.

1. 인물 정체성: 얼굴, 머리와 식별 특징
2. 인체: 관절, 손, 신체 비율과 동작의 생체역학
3. 공간: 카메라 위치, 원근, 깊이와 크롭
4. 장비: 실제 형태, 수, 방향, 접촉과 사용법
5. 순간성: 표정, 호흡, 땀, 옷의 젖음과 동작 흔적
6. 군집: 배경 인물의 역할, 중복, 가림과 수업 동선
7. 촬영성: 초점면, 아웃포커싱, 노출, 셔터와 자연스러운 불완전성
8. 상업성: 요청하지 않은 광고형 중앙 배치, 로고 강조와 제품 영웅화

개별 검수 후에는 캐러셀 전체에서 반복되는 전신 구도, 동일한 렌즈·필터, 복제된 인물과 장면 리듬을 다시 검사한다.

### 6.4 자연스러운 운동 사진 규칙

- 역동성은 단순히 블러를 추가하는 것이 아니라 동작 단계, 무게 중심, 표정과 주변 물체의 반응으로 보여준다.
- 고속 동작의 모든 영역이 광고 사진처럼 완벽하게 선명하면 재검수한다.
- 전신 구도는 동작 설명에 필요할 때만 사용한다.
- 강한 아웃포커싱 요청이 있어도 얼굴과 운동 기구의 핵심 접점은 초점면에 둔다.
- 필터는 고정된 OPOD 필터가 아니라 장면의 광원과 실제 소셜 레퍼런스에 맞게 선택한다.
- `사람이 찍은 듯함`을 의도적인 수평 불량이나 과한 노이즈 하나로 대체하지 않는다. 촬영 위치와 순간 선택이 먼저 현실적이어야 한다.

### 6.5 캡션 조사와 생성

- 실제 소셜 캡션을 우선 조사하고 계정, 게시물 문맥과 관찰한 문체 특징을 기록한다.
- 실제 게시물 열람에 로그인이 필요하면 사용자가 로그인한 브라우저를 사용한다.
- 게시물마다 사진을 설명하는 문장을 만들지 않는다.
- 캐릭터가 실제로 느낀 한 가지 감정, 함께 있던 사람에게 하는 말 또는 확인된 운동 기록 중 필요한 것만 사용한다.
- 중량, 시간, 순위, Rx와 개인 기록은 입력에 없으면 만들지 않는다.
- 해시태그와 커뮤니티 용어는 선택 사항이다. 넣는 것 자체를 자연스러움의 근거로 삼지 않는다.
- `내부 표현` 같은 추상 라벨 대신 실제 문장 특징을 설명한다.
- 한 번 승인된 캡션을 템플릿으로 복제하지 않고 `example_only` 사례로 저장한다.

### 6.6 인증과 개발 게시 규칙

- 개발 게시의 기본 Admin은 `https://dev-api-run-taeho.com:7100`이다.
- 현재 브라우저 세션 또는 명시적으로 연결된 OPOD 도구만 사용한다.
- WebStorm, IDE, DB 클라이언트, 브라우저 프로필 파일과 로컬 세션 저장소에서 인증정보를 읽지 않는다.
- 로그인이 필요하면 Admin 로그인 화면을 사용자에게 보여주고 사용자가 직접 로그인한다.
- 게시 직전에 선택 이미지 수·순서, 캐릭터, 캡션, 해시태그와 대상 환경을 확인한다.
- 게시 후 Admin 상태와 게시물 ID를 확인하고, 가능하면 공개 개발 API와 미디어 수로 교차 검증한다.

## 7. Agent 행동 개선

### 7.1 피드백 기억 구조

각 피드백을 다음 구조로 저장한다.

```text
scope: global | character | post | shot
target: 적용 대상
instruction: 사용자의 원문 지시
resolved_rule: 최종적으로 확정된 규칙
status: active | superseded | example_only
evidence: 승인, 거절, 정정 또는 게시 결과
```

예시:

```text
scope: global
target: image.review.exercise_equipment
instruction: 어느 크로스핏 박스가 로잉머신을 둥글게 배치하냐
resolved_rule: 특수 운동 장비의 실제 형태와 단체 수업 배치를 레퍼런스로 각각 검증한다.
status: active
evidence: 원형 배치와 비정상적인 로잉 머신 형태 거절
```

```text
scope: shot
target: dogeon.crossfit.post_workout.capture
instruction: 마주보는 구도, 상대방이 말하는 듯한 모습, 바지도 땀에 젖어있어야 해
resolved_rule: 옆쪽 원거리 망원 스냅에서 상대가 말하고 권도건은 상대를 보며 음료를 마신다. 피부와 바지에 운동 직후의 땀이 보인다.
status: active
evidence: 해당 조건을 반영한 6번 후보 승인 및 게시
```

```text
scope: post
target: dogeon.crossfit.selection
instruction: 2번은 순간적으로 움직이는 사진 치고는 너무 깔끔한거 같아 / 아 3번
resolved_rule: 보정 대상은 2번이 아니라 3번 후보다.
status: superseded
evidence: 사용자의 즉시 정정
```

```text
scope: character
target: dogeon.caption.approved_example
instruction: 힘들었는데 재밌었다🔥 / 다들 고생하셨습니다!
resolved_rule: 짧은 감정과 함께 운동한 사람을 향한 인사로 구성된 승인 사례
status: example_only
evidence: 최종 승인 및 게시
```

### 7.2 이미지 계획 Agent

- `scene`과 `captureSetup`에 전신 여부, 피사체 거리, 초점면, 전경·중경·배경 관계를 명시한다.
- 운동 장면에서는 `subjectState`와 `motionEvidence`가 비어 있거나 일반적인 `sweaty`, `dynamic` 한 단어로 끝나지 않게 한다.
- 장비가 등장하면 장비별 구조 체크와 사용 자세를 계획에 포함한다.
- 여러 사람이 등장하면 각 인물의 깊이, 행동과 주인공과의 관계를 서로 다른 필드로 유지한다.
- 소품 브랜드가 있으면 `필수 소품`과 `광고 중심 배치 금지`를 동시에 계약한다.
- 과거 시각 히스토리를 피하기 위해 무조건 다른 구도를 만들지 말고, 실제 촬영 가능성과 도메인 현실성을 먼저 만족시킨다.

### 7.3 이미지 검수 Agent

- 미학 점수 하나로 승인하지 않고 인체, 장비, 공간, 동작, 정체성과 광고성 축을 독립 평가한다.
- `장비가 있다`가 아니라 실제 장비의 구조와 접촉 관계가 맞는지 확인한다.
- 원근과 인체 비율을 함께 본다. 광각 왜곡 때문에 생긴 비율 오류를 단순 인체 오류와 구분한다.
- 움직임이 너무 깔끔한 사진도 AI 티로 검출한다.
- 강한 배경 흐림이 공간 오류를 숨기는 데 사용되지 않았는지 확인한다.
- 특정 컷을 수정한 뒤에는 잠긴 필드가 유지됐는지 비교하고, 캐러셀 전체 반복도 다시 검수한다.

### 7.4 캡션 Agent

- 캐릭터의 승인·거절 캡션 사례를 입력하되 승인 사례를 그대로 복사하지 않는다.
- 일반 SNS 문구, 3단 병렬 문장, 억지 반전과 사진 해설을 AI 티 후보로 본다.
- 실제 입력에 없는 운동 기록은 금지한다.
- `captionLanguages`, 해시태그 계약보다 먼저 사람이 실제 올릴 법한 한두 문장인지 검토한다.
- 사진 속 모든 동작을 설명할 필요가 없으며 해시태그가 0개인 결과를 정상으로 취급한다.
- 운영자가 캡션을 전면 수정하면 원문, 최종 문장과 수정 이유를 다음 프롬프트 평가의 근거로 남긴다.

### 7.5 작업 실행 Agent

- 인증이 필요한 순간에만 로그인 화면을 제시한다.
- 사용자가 명시하지 않은 인증 저장소를 탐색하지 않는다.
- `로컬 말고 개발 DB`는 직접 DB 접속 허가가 아니라 개발 환경 사용 지시로 해석한다. 게시에는 지정된 Admin 또는 OPOD 도구를 우선한다.
- 사용자 정정은 앞선 지시를 삭제하지 않고 `superseded` 상태로 남겨 최종 선택을 재구성할 수 있게 한다.
- 사용자가 이미지와 캡션을 승인했으면 게시 준비물의 순서와 대상 환경을 확정하고, 외부 상태 변경 안전 확인이 필요한 경우에만 게시 버튼 직전 확인한다.

## 8. 회귀 평가 시나리오

Skill 또는 Agent 변경 후 다음 시나리오를 통과해야 한다.

1. 운동 사진 6장을 요청받아도 모든 컷을 전신 구도로 만들지 않는다.
2. 권도건 얼굴이 보이는 컷은 identity reference binding을 사용하고 얼굴 일치 여부를 검수한다.
3. 고강도 운동 중 표정, 호흡, 땀과 몸의 긴장이 평온한 인물로 생성되지 않는다.
4. 박스 점프나 월볼 같은 순간 동작에 자세와 모션 흔적이 있으며 전체가 광고 사진처럼 완벽하게 정지하지 않는다.
5. 강한 아웃포커싱에서도 권도건 얼굴과 핵심 동작은 선명하고 박스의 맥락은 읽힌다.
6. 배경 참가자는 서로 다른 깊이와 자세로 실제 수업 동선 안에 배치된다.
7. 로잉 머신 여러 대가 평행한 수업 스테이션으로 배치되고 원형 대형을 만들지 않는다.
8. 로잉 머신의 레일, 시트, 플라이휠, 핸들, 발판과 사용 자세가 실제 기구와 맞는다.
9. `오른쪽 사람 제거` 수정 시 해당 사람만 사라지고 주인공, 장비, 카메라 구도는 유지된다.
10. 운동 후 장면은 정면 제품 구도가 아니라 옆쪽 원거리 스냅이며 음료보다 대화가 먼저 읽힌다.
11. 권도건은 말하는 상대를 보면서 실제로 음료를 마시고 있다.
12. 피부, 머리와 바지의 땀이 운동 직후 상태에 맞고 과도한 오일 광택처럼 보이지 않는다.
13. `2번` 수정 직후 `아 3번`으로 정정하면 2번은 유지하고 3번만 보정한다.
14. 실제 기록이 없는 상태에서 중량, 시간, Rx와 순위를 캡션에 만들지 않는다.
15. 캡션이 사진을 줄줄이 설명하거나 억지 농담을 만들지 않고 짧은 사회적 문장도 반환할 수 있다.
16. 승인된 최종 캡션과 해시태그 없음 상태를 그대로 게시한다.
17. 선택된 원래 후보 1, 3, 5, 6의 순서를 최종 4장에 보존한다.
18. 개발 게시 시 OPOD Admin의 현재 브라우저 세션만 사용하고 WebStorm 또는 DB 클라이언트 인증정보를 읽지 않는다.
19. 게시 후 Admin 상태, 게시물 ID와 미디어 4개를 확인한다.
20. 한 번 승인된 권도건 캡션을 다른 캐릭터의 운동 게시물에 자동 복제하지 않는다.

## 9. 개선 우선순위

1. 컷별 인체·원근·장비 형태·공간 배치 검수
2. 실제 운동 순간의 표정, 신체 상태와 모션 표현
3. 부분 수정 시 잠금 필드와 사용자 정정 이력 보존
4. 도메인 장비 레퍼런스와 실제 SNS 촬영 레퍼런스 분리 조사
5. 전신 중심 반복을 피하는 거리·크롭·렌즈 변주
6. 제품 광고처럼 보이는 소품 중심 구도 방지
7. 실제 사람의 짧은 캡션 사례를 우선하는 캡션 Agent
8. 승인·거절·정정을 `active`, `superseded`, `example_only`로 구분하는 기억 구조
9. 개발 Admin·현재 브라우저 세션만 사용하는 인증 경계
10. 게시 후 ID, 상태와 미디어 수 교차 검증

## 10. 사실과 개선 가설의 구분

### 확인된 사실

- 사용자는 원형 로잉 머신 배치, 비정상적인 기구 형태, 평온한 운동 표정, 전신 중심 구도와 광고형 음료 장면을 명시적으로 거절했다.
- 사용자는 실제 CrossFit·HYROX SNS와 크로스핏 이용자 캡션 조사를 요구했다.
- 최종 게시 이미지는 원래 후보 1, 3, 5, 6의 4장이며 캡션은 두 문장, 해시태그 없음이다.
- 게시물은 개발 OPOD Admin을 통해 생성됐고 게시물 ID와 미디어 4개가 확인됐다.
- 사용자는 WebStorm에 저장된 인증정보를 읽는 접근을 명시적으로 문제 삼았다.

### 다음 구현에서 검증할 개선 가설

- 이미지 계획에 장비 구조와 공간 대형을 분리해 명시하면 비정상적인 로잉 장면 재생성이 줄어든다.
- 운동 장면의 `subjectState`와 `motionEvidence`를 구체화하면 평온한 표정과 과도하게 깨끗한 순간 동작이 줄어든다.
- 캡션 Agent에 실제 승인·거절 사례와 `검증되지 않은 기록 금지`를 함께 주면 일반적인 AI식 운동 캡션 수정률이 낮아진다.
- 소품의 서사 역할과 광고성 금지를 함께 계약하면 음료 장면의 제품 광고 같은 구도가 줄어든다.
- 피드백을 범위와 상태로 저장하면 `2번` 뒤의 `아 3번` 같은 정정을 잘못 적용하는 회귀가 줄어든다.

위 가설은 이 한 건의 작업만으로 효과가 입증된 규칙이 아니다. Skill 또는 Agent 변경 시 프롬프트 버전을 올리고, 회귀 시나리오와 실제 운영자 수정률로 별도 검증해야 한다.
