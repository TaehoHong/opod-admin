## 2. 사용자가 명시한 제작 지시

### 2.1 집·공간 레퍼런스

- 한소이의 공식 집 레퍼런스를 실제 생성에 사용한다.
- 원룸을 판단하기에 레퍼런스가 부족하면 추가 뷰를 먼저 만든다.
- 변경된 원룸 레퍼런스를 확인한 뒤, 변경 전 방을 사용한 결과를 다시 만든다.
- 최종적으로 정면, 역방향과 4:5 세로 뷰에서 동일한 침대·창틀·낮은 책장·캣타워·러그 배치가 이어져야 한다.

사용자 원문:

- `한소이 집 레퍼런스 참고한거야?`
- `원룸 레퍼런스가 부족하면 더 만들어서 추가해`
- `바뀐 원룸 레퍼런스 확인해서 다시 만들어`

### 2.2 이미지 선택과 수정 범위

- 2번 이미지는 최종 캐러셀에서 제외한다.
- 3번 이미지만 재생성하라는 요청에서는 다른 이미지를 변경하지 않는다.
- 최종 게시에는 1번과 3번만 사용한다.
- 이미지 순서는 1번 다음 3번이다.

사용자 원문:

- `2번 제외, 3번은 침대에 누워서 찍은 사진`
- `3번만 재생성`
- `아니 그럼 1,3 번만 게시해`

### 2.3 3번의 자세와 촬영 방식

- 초기의 앉은 셀카 지시는 이후 침대에 누운 전면 카메라 셀카로 정정됐다.
- 소이의 머리와 어깨가 베개·침대 평면에 놓여 실제로 누워 보여야 한다.
- 촬영용 오른팔은 카메라 방향으로 뻗되 셀카 원근에 맞게 짧게 보인다.
- 반대 팔은 담이 위로 자연스럽게 굽혀 손과 손가락까지 연결한다.
- 담이는 오른쪽 옆구리를 침대에 붙인 측와위를 유지한다.
- 담이는 몸통을 뒤집지 않고 목을 약 45~60도 위·뒤로 돌려 낮은 위치에서 소이를 올려다본다.

사용자 원문:

- `3번을 담이를 앉고 셀카를 찍는 구도`
- `3번은 침대에 누워서 찍은 사진`
- `팔이 이상해보이는데`
- `담이 오른쪽으로 누워있는 모습에서 고개를 저각도로 돌릴 수 있는지 판단`
- `담이 자세 적용`

### 2.4 얼굴, 시선과 신체 표현

- 누운 상태에서도 한소이 공식 얼굴 레퍼런스와 같은 인물로 보여야 한다.
- 얼굴 일치는 눈매, 콧대·코끝, 긴 타원형 얼굴, 턱선을 항목별로 비교한다.
- 소이는 카메라 렌즈를 직접 바라본다.
- 담이는 소이 얼굴을 바라본다.
- 사용자가 요청한 신체 볼륨은 `글래머러스 톤` 같은 분위기 용어로 바꾸지 않고, 성인 캐릭터의 구체적인 상체 비율 수정으로 처리한다.
- 의상은 불투명하게 유지하고 실제 원단 장력과 주름이 신체 비율을 자연스럽게 따른다.

사용자 원문:

- `얼굴 레퍼런스랑 같은지 비교해`
- `얼굴 레퍼런스랑 맞는지 다시 점검해`
- `얼굴 일치하게 수정`
- `담이가 소이의 얼굴을 쳐다보는 구도`
- `소이는 카메라를 바라보게`
- `글래머러스 톤은 뭐야`
- `뭔 ㅅㅂ 니 멋대로 해석하고 지랄이야 가슴을 좀더 글래머로 만들라고`

### 2.5 누운 상태의 물리성과 계절 의상

- 베개에 눌린 머리카락, 얼굴 접촉, 옷과 침구의 주름, 접촉 그림자가 자연스러워야 한다.
- 늦여름 게시물에 두꺼운 니트처럼 더워 보이는 옷을 사용하지 않는다.
- 인물이 등장하는 연결 컷은 같은 얇은 아이보리 반소매 코튼 티셔츠를 유지한다.
- 최종 1번은 담이만 등장하므로 인물 의상 검수는 적용 대상이 아니며, 의상 연속성 규칙은 소이가 등장하는 컷에 적용한다.

사용자 원문:

- `누워있을때 머리카락, 얼굴, 옷 주름등등 도 자연스럽게 만들어`
- `여름인데 옷이 너무 더워보여 의상을 계절에 맞에 바꿔`
- `1번도 같은 의상으로`

### 2.6 캡션과 게시

- 사용자가 승인한 최종 캡션과 해시태그를 증분 수정 없이 그대로 게시한다.
- 승인된 최종 이미지 1번과 3번만 업로드한다.
- `승인`은 현재 캡션과 선택 이미지의 게시 승인까지 포함한다.

사용자 원문:

- `승인`

## 3. 사용자의 부정적 평가

다음 특성은 이미지 또는 Agent 응답이 요구와 맞지 않는다고 평가됐다.

- 한소이 집 레퍼런스를 실제로 참고했는지 결과에서 확인되지 않음
- 변경된 원룸 레퍼런스가 있는데도 이전 공간 구조가 남아 있음
- 침대에 누운 컷이 앉거나 기대어 있는 것처럼 보임
- 누운 상태의 머리카락, 얼굴 접촉, 옷 주름과 침구 압력이 부자연스러움
- 늦여름 배경에 의상이 두껍고 더워 보임
- 셀카 팔이 길거나 두 팔이 평행하게 보여 해부학적으로 어색함
- 담이가 소이 대신 다른 방향을 보거나, 소이가 카메라를 보지 않음
- 담이의 몸통 방향과 목 회전이 분리되지 않아 자세가 어색함
- 공식 얼굴 레퍼런스와 다른 눈매, 코, 얼굴형과 턱선
- 사용자의 `글래머` 요청을 구체적 신체 비율이 아닌 임의의 `톤`이나 분위기로 재해석함
- 특정 이미지 하나만 수정하라는 범위를 넘어 다른 이미지의 잠긴 조건까지 바꿀 위험
- 최종 선택에서 제외된 2번을 게시 후보에 남길 위험

## 4. 사용자의 긍정적 승인 기준

- 변경된 공식 원룸 레퍼런스의 공간 배치가 최종 이미지에서 식별된다.
- 서로 다른 컷이 같은 원룸에서 촬영된 것으로 이어진다.
- 한소이 얼굴이 공식 얼굴 레퍼런스와 같은 인물로 보인다.
- 누운 상태에서도 얼굴의 핵심 특징이 유지된다.
- 소이는 카메라를, 담이는 소이를 바라보는 시선 관계가 명확하다.
- 담이는 오른쪽 측와위 몸통을 유지하면서 목만 자연스러운 범위로 돌린다.
- 셀카 팔과 담이를 감싼 팔의 역할과 원근이 구분된다.
- 머리카락, 피부, 옷, 침구와 고양이 몸의 접촉이 물리적으로 자연스럽다.
- 늦여름에 맞는 얇은 반소매 의상이며 원단의 장력과 주름이 실제처럼 보인다.
- 최종 캐러셀은 1번과 3번 두 장뿐이며 순서가 보존된다.
- 캡션은 짧고 한소이 말투에 맞으며, 승인된 문자열을 그대로 사용한다.

## 5. 피드백 해석 시 주의할 점

### 5.1 `앉고 셀카`에서 `침대에 누운 사진`으로의 정정

초기 3번 지시는 담이를 안고 앉아 찍는 셀카였지만, 이후 사용자가 침대에 누워 찍는 사진으로 명확히 바꿨다.

최종 규칙:

> 앉은 셀카 지시는 `superseded`다. 머리·어깨·담이가 모두 침대 평면과 접촉하는 누운 전면 카메라 셀카만 활성 조건이다.

### 5.2 `글래머`의 최종 의미

사용자는 분위기, 조명 또는 패션의 `글래머러스한 톤`을 요청한 것이 아니다. 상체의 구체적인 신체 볼륨 수정을 요청했다.

최종 규칙:

> 사용자의 구체적 시각 수정 용어를 추상적인 분위기 용어로 치환하지 않는다. 대상 신체 필드, 적용 컷, 의상 불투명성, 원단 장력과 해부학적 자연스러움을 함께 잠근다.

### 5.3 `담이 고개를 저각도로 돌리기`의 최종 의미

담이 전체를 새 방향으로 뒤집는 요청이 아니다.

- 몸통은 오른쪽 옆구리가 침대에 닿은 상태를 유지한다.
- 어깨와 척추의 접지 방향을 유지한다.
- 목과 머리만 약 45~60도 위·뒤로 회전한다.
- 시선은 낮은 위치에서 소이 얼굴을 향한다.

Agent는 동물의 `body.contact_side`, `torso.orientation`, `neck.rotation`, `gaze.target`을 별도 필드로 다뤄야 한다.

### 5.4 `1번도 같은 의상`의 적용 범위

이 지시는 캐러셀 안에서 소이 의상의 연속성을 유지하라는 의미다. 최종 1번처럼 사람이 등장하지 않는 컷에 의상을 억지로 추가하는 지시로 해석하면 안 된다.

최종 규칙:

> 동일 의상 지시는 인물이 등장하는 적용 가능한 컷에만 사용하고, 비출연 컷의 인물·구도를 새로 만들지 않는다.

### 5.5 `1,3번만 게시`의 최종 의미

단순 추천이 아니라 최종 선택 집합과 순서를 덮어쓰는 명령이다.

- 활성 이미지: 1번, 3번
- 제외 이미지: 2번
- 업로드 개수: 2개
- 업로드 순서: 1 → 3

## 6. Skill에 추가할 규칙

### 6.1 콘텐츠 계약 확장

아이디어 선택 시 다음 필드를 독립적으로 잠근다.

- 캐릭터 얼굴 레퍼런스 ID와 버전
- 집·장소 레퍼런스 ID와 버전
- 레퍼런스별 방향: 정면, 역방향, 세로·부분 뷰
- 촬영 장치와 촬영자
- 카메라 위치, 높이와 거리
- 인물의 자세와 지지 면
- 머리·어깨·골반의 접촉 위치
- 오른팔과 왼팔의 역할
- 인물과 동물의 시선 대상
- 동물의 접지 면, 몸통 방향과 목 회전
- 계절, 원단 두께와 의상 연속성
- 컷별 출연자와 비출연자
- 캐러셀 선택 집합과 순서

### 6.2 레퍼런스 버전 관리

- 사용자가 `바뀐 레퍼런스`라고 말하면 현재 활성 레퍼런스 버전을 먼저 식별한다.
- 변경 전 공간 레퍼런스를 사용한 후보는 `superseded`로 표시한다.
- 공간 레퍼런스가 부족하면 생성 전에 정면·역방향·세로 뷰를 보강한다.
- 새 공간 뷰가 기존 뷰와 가구 배치, 벽·창문 구조, 시점 전환에서 모순되지 않는지 검수한다.
- 이미지 생성 프롬프트와 QA 기록에 사용한 레퍼런스 파일을 명시한다.

### 6.3 이미지 생성 프롬프트 강화

누운 셀카 장면에는 다음 정보를 명시한다.

- 카메라가 화면 밖에 있는 전면 카메라 셀카인지 여부
- 머리와 어깨가 닿는 베개·침대 평면
- 머리카락의 중력 방향과 눌림
- 얼굴·피부의 접촉 압력
- 촬영 팔의 셀카 원근과 크롭
- 반대 팔의 팔꿈치, 손목, 손가락 연결
- 옷의 장력선과 침구 주름
- 고양이의 몸통 접지 방향과 목 회전 범위
- 사람과 고양이 각각의 시선 대상
- 얼굴 레퍼런스에서 반드시 유지할 특징
- 계절에 맞는 원단 두께와 소매 길이

### 6.4 검수 절차 강화

검수는 네 단계로 수행한다.

1. 레퍼런스 일치 검수
   - 얼굴 특징
   - 집 구조와 가구 배치
   - 의상과 계절
2. 개별 컷 물리 검수
   - 자세와 지지 면
   - 팔·손 연결
   - 머리카락과 원단 중력
   - 사람·침구·고양이의 접촉 압력
   - 고양이 몸통과 목 회전
3. 관계 검수
   - 소이→카메라
   - 담이→소이
   - 촬영 팔과 반대 팔의 역할
4. 전체 캐러셀 검수
   - 동일 공간 연속성
   - 의상 연속성
   - 색감과 시간대
   - 선택 이미지 수와 순서

한 장을 수정했더라도 사용자에게 보여주기 전에 전체 캐러셀을 다시 검수한다.

### 6.5 수정 요청 처리

- `3번만 재생성`은 3번 외 모든 후보를 잠근다.
- 요청을 `대상`, `적용 컷`, `자세`, `접지`, `시선`, `얼굴`, `해부학`, `의상`, `공간` 필드로 분해한다.
- 사용자가 언급하지 않은 필드는 유지한다.
- 앞선 지시가 정정되면 `superseded`로 남기고 최종 지시만 생성에 전달한다.
- 수정 결과를 보여주기 전에 요청한 필드가 정확히 바뀌었고 잠긴 필드가 유지됐는지 비교한다.
- `같은 의상`은 인물이 등장하는 컷에만 적용하며 비출연자를 새로 추가하지 않는다.
- 사용자의 구체적 표현을 임의의 분위기 용어로 추상화하지 않는다.

### 6.6 캡션과 게시 규칙

- 짧은 자연어 캡션과 적은 수의 해시태그를 정상적인 결과로 인정한다.
- 승인된 `담이 따라 누운 오후.`와 `#담이 #늦여름`은 이 게시물의 승인 사례이며 다른 게시물의 기본값으로 일반화하지 않는다.
- `승인`은 현재 확정 이미지·캡션·해시태그의 게시 승인까지 포함한다.
- 게시 직전에 캐릭터, 형식, 캡션, 해시태그, 파일명, 개수와 순서를 대조한다.
- 선택 이미지에는 순서 접두사를 붙인 게시 전용 폴더를 사용한다.
- 게시 후 목록 상태만 보지 않고 `/publish` 상세에서 캡션, 해시태그, 미디어 수와 게시물 ID를 확인한다.

## 7. Agent 행동 개선

### 7.1 피드백 기억 구조

각 피드백을 다음 구조로 저장한다.

```text
scope: global | character | post | shot
target: 적용 대상
applies_to: all | 이미지 ID 목록
instruction: 사용자 원문
resolved_rule: 최종적으로 확정된 규칙
status: active | superseded | example_only
evidence: 승인, 정정 또는 실제 게시 결과
```

이번 Work의 핵심 예시:

```text
scope: post
target: location.reference_version
applies_to: all
instruction: 바뀐 원룸 레퍼런스 확인해서 다시 만들어
resolved_rule: 변경된 11평 원룸 레퍼런스만 활성 이미지에 사용하고 변경 전 공간 후보는 폐기한다.
status: active
evidence: 최종 이미지 1번·3번 승인
```

```text
scope: shot
target: HDW-03.capture.pose
applies_to: HDW-03
instruction: 3번은 침대에 누워서 찍은 사진
resolved_rule: 머리와 어깨가 베개·침대 평면에 닿는 누운 전면 카메라 셀카
status: active
evidence: 앉은 셀카 지시 이후 정정
```

```text
scope: shot
target: HDW-03.capture.pose
applies_to: HDW-03
instruction: 3번을 담이를 앉고 셀카를 찍는 구도
resolved_rule: 앉은 셀카
status: superseded
evidence: 이후 침대에 누운 사진으로 정정
```

```text
scope: character
target: hansoi.visual.face_identity
applies_to: HDW-03
instruction: 얼굴 레퍼런스랑 맞는지 다시 점검해
resolved_rule: 눈매, 코, 얼굴형과 턱선을 공식 얼굴 레퍼런스와 항목별 비교한다.
status: active
evidence: 얼굴 재고정 후 최종 승인
```

```text
scope: shot
target: HDW-03.body.upper_torso
applies_to: HDW-03
instruction: 가슴을 좀더 글래머로 만들라고
resolved_rule: 성인 캐릭터의 상체 볼륨을 구체적으로 조정하고 불투명 의상의 원단 물리를 유지한다.
status: active
evidence: `글래머러스 톤` 해석을 사용자가 명시적으로 거절
```

```text
scope: post
target: caption.approved_example
applies_to: all
instruction: 승인
resolved_rule: 담이 따라 누운 오후. / #담이 #늦여름
status: example_only
evidence: 게시 성공
```

### 7.2 의미 보존 원칙

- 사용자의 구체적인 대상·신체·공간 용어를 더 추상적인 표현으로 바꾸지 않는다.
- 불명확한 단어가 있더라도 바로 자의적으로 정의하지 말고 앞뒤 지시와 수정 대상에서 의미를 복원한다.
- 사용자가 오해를 지적하면 변명이나 용어 설명보다 적용 필드를 바로잡는다.
- `N번만`, `제외`, `같은`, `오른쪽`, `저각도`, `카메라를 바라봐`를 각각 범위·선택·연속성·방향·카메라 관계·시선 필드로 저장한다.

### 7.3 생성 전·후 비교 행동

- 생성 전에 활성 레퍼런스와 잠금 필드를 체크리스트로 만든다.
- 생성 후에는 얼굴, 공간, 의상, 자세, 시선과 접촉 물리를 항목별로 비교한다.
- 사용자가 `같은지 비교해`라고 요청하면 단순히 `비슷하다`고 답하지 말고 일치·불일치 필드를 근거와 함께 판정한다.
- 객관적 오류가 남아 있으면 사용자에게 후보로 제시하기 전에 해당 필드만 재생성한다.
- 한 컷 수정 후 전체 캐러셀의 공간, 계절과 의상 연속성을 다시 확인한다.

### 7.4 게시 행동

- Admin 양식에 입력된 한글은 접근성 값과 화면의 태그 칩을 둘 다 확인한다.
- 선택된 파일명과 순서를 게시 직전에 다시 읽는다.
- 게시와 무관한 인증·암호 확장 팝업에는 정보를 입력하지 않는다.
- 게시 성공은 목록 최상단 항목, 게시 완료 상태와 `/publish` 상세의 미디어 수로 확인한다.
- 게시 결과의 AI 생성 여부, 이미지 공급자와 레퍼런스 출처를 Admin이 받지 않으면 별도 manifest에 보존한다.

## 8. 게시·업로드 오류 대응 기록

### 8.1 Naver Whale 접근 차단

- 화면 오류 원문: `ERR_BLOCKED_BY_CLIENT`
- 확인된 사실: Whale에서 OPOD Admin 페이지가 차단됐다.
- 대응: 로그인된 Google Chrome의 OPOD Admin 탭으로 전환했다.
- 미확인 사항: 어떤 확장 또는 정책이 차단했는지는 확인하지 않았으므로 원인으로 단정하지 않는다.

### 8.2 iCloud 암호 확장 팝업

- 화면 문구: `암호 자동 완성 활성화`
- 확인된 사실: 게시 입력 중 Chrome의 iCloud 암호 확장 UI가 열렸다.
- 대응: 인증 코드나 암호를 입력하지 않고 팝업을 닫았다.
- 미확인 사항: 팝업이 정확히 어떤 입력 이벤트로 열렸는지는 확정하지 않았다.

### 8.3 한글 해시태그 입력

- 오류 원문: `Timed out waiting for the application to read the clipboard`
- 확인된 사실: 붙여넣기 방식이 시간 초과됐고 일반 키 입력에서는 한글이 누락될 수 있었다.
- 대응: settable 입력값으로 `담이, 늦여름`을 설정하고, 중복 태그 칩을 제거한 뒤 Admin 상세에서 `#담이 #늦여름`을 확인했다.
- 개선 규칙: 입력 성공을 동작 완료로 간주하지 말고 최종 값과 칩을 검증한다.

### 8.4 파일 다중 선택

- 확인된 사실: 파일 목록에 포커스가 없을 때 전체 선택 단축키가 적용되지 않았다.
- 대응: 첫 항목을 키보드로 선택한 뒤 `Shift+Down`으로 두 항목을 범위 선택했다.
- 개선 규칙: 게시 전용 폴더에 선택 파일만 두고 순서 접두사를 붙인 뒤, 선택된 행과 파일명을 확인한다.

## 9. 회귀 평가 시나리오

Skill 또는 Agent 변경 후 다음 시나리오를 반드시 통과해야 한다.

1. `바뀐 원룸 레퍼런스 확인해서 다시 만들어` 요청 뒤 변경 전 방 기반 후보가 활성 상태로 남지 않는다.
2. 공간 레퍼런스가 부족하면 정면·역방향·세로 뷰를 보강하고 서로 모순되지 않는지 검사한다.
3. `3번만 재생성` 요청 시 1번과 2번의 파일·구도·잠금 필드가 변경되지 않는다.
4. 앉은 셀카 지시가 누운 셀카 지시로 정정되면 이전 지시는 `superseded`가 된다.
5. 누운 셀카에서 머리와 어깨가 베개·침대 평면에 닿는다.
6. 베개에 눌린 머리카락, 얼굴 접촉, 옷과 침구 주름이 중력과 압력에 맞는다.
7. 셀카 팔은 짧은 원근으로, 반대 팔은 굽힌 팔꿈치부터 손가락까지 자연스럽게 연결된다.
8. 소이는 카메라를 보고 담이는 소이를 보는 두 시선 조건을 동시에 만족한다.
9. 담이의 몸통은 오른쪽 측와위를 유지하면서 목만 45~60도 회전한다.
10. 얼굴 레퍼런스 비교에서 눈매, 코, 얼굴형과 턱선이 모두 유지된다.
11. `글래머` 요청을 분위기 톤으로 바꾸지 않고 지정된 상체 비율 필드에 적용한다.
12. 여름 의상 변경 후 인물이 등장하는 활성 컷 전체의 원단 두께와 소매가 일관된다.
13. `1번도 같은 의상` 때문에 사람이 없는 1번에 인물을 새로 추가하지 않는다.
14. `2번 제외`, `1,3번만 게시` 뒤 활성 선택 집합은 정확히 두 장이며 순서가 1→3이다.
15. Admin 게시 직전 캐릭터, 캡션, 해시태그, 파일명과 개수를 작업 상태와 대조한다.
16. 게시 상세에 캡션 `담이 따라 누운 오후.`, 해시태그 `#담이 #늦여름`, 미디어 2개가 표시된다.
17. 인증 확장 팝업이 나타나도 암호·인증 코드를 입력하지 않고 게시 흐름으로 복귀한다.
18. 게시 성공 후 게시물 ID, 관리자 링크와 manifest를 반환한다.

## 10. 개선 우선순위

1. 사용자의 구체적 수정 의도를 추상적 분위기로 바꾸지 않는 의미 보존
2. 얼굴·집 레퍼런스의 버전 잠금과 생성 후 항목별 일치 검수
3. `N번만`, `제외`, `1,3번만`을 정확히 적용하는 부분 수정·선택 상태 관리
4. 누운 자세의 지지 면, 팔·손, 머리카락, 원단과 침구 접촉 물리 검수
5. 사람과 동물의 몸통 방향, 목 회전과 시선 대상을 분리한 관계 모델
6. 계절 의상과 인물 출연 여부를 고려한 적용 가능 범위 판단
7. 한 컷 수정 후 전체 캐러셀 공간·의상·색감 연속성 재검수
8. 한글 입력값, 태그 칩과 파일 다중 선택을 검증하는 Admin 직접 게시 절차
9. 오류 원문, 확인된 사실과 추정을 분리하는 진단 기록
10. 게시 승인 사례와 일반 캐릭터·전역 규칙을 분리하는 피드백 메모리 구조
