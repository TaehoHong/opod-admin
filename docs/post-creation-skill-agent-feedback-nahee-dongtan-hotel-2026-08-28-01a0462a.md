## 2. 사용자가 명시한 제작 지시

### 2.1 레퍼런스 조사

- 우선순위 1의 직접 레퍼런스가 나오지 않으면 조사를 멈추지 않는다.
- 직접 일치하는 자료가 부족하면 나희의 페르소나 특징을 실제 공개 콘텐츠에서 보여주는 성인 크리에이터를 조사한다.
- 나희의 핵심 페르소나는 단순한 우아함이 아니라 자신감 있고 주도적인 성인 패션 섹스어필이다.
- `동탄룩`을 Agent의 기억만으로 해석하지 말고 실제 소셜·웹 용례를 조사한다.
- 캡션이 실제 사람의 글처럼 보이지 않으면 실제 Instagram 게시물의 캡션을 다시 조사한다.
- 조사에 로그인이 필요하면 임의로 우회하지 말고 사용자에게 로그인을 요청한다.

### 2.2 사진의 분위기와 의상

- 사진은 화보처럼 완벽하게 연출된 결과가 아니라 개인이 호캉스 중 자연스럽게 찍은 소셜 사진처럼 보여야 한다.
- 호텔의 우아하고 고급스러운 분위기는 보조 요소이며, 나희의 섹스어필을 대체하면 안 된다.
- 의상은 조사한 `동탄룩`의 대표적 실루엣을 반영한다.
- 이번 게시물에서는 딥 버건디 밀착 니트 미디 원피스를 세 장 모두 동일하게 유지한다.

### 2.3 인물과 구도

- 손의 품질을 모든 사진에서 개선한다.
- 가슴 볼륨을 모든 사진에서 더 크게 표현하되 나희의 기존 글래머 체형 안에서 일관성을 유지한다.
- 측면으로 돌아선 뒤 골반을 뒤로 두고 카메라를 바라보는 구도를 새 이미지로 만든다.
- 상체를 숙인 구도를 별도 변주로 시도한다.
- 안전한 대안으로 구도를 임의 조정해 끝내지 말고, 사용자가 요청한 시도와 Agent가 제안한 두 대안을 함께 만들어 총 3개 후보로 비교한다.

### 2.4 캡션

- 실제 개인 계정 사용자가 쓴 것처럼 짧고 자연스러워야 한다.
- 문구는 `간만에 호캉스`로 한다.
- 서로 다른 색의 하트 세 개를 붙인다.
- 호텔 `🏨`과 반짝임 `✨` 이모지는 제외한다.
- 최종 문구는 `간만에 호캉스 ❤️🧡💜`이며 해시태그는 사용하지 않는다.

## 3. 사용자의 부정적 평가

다음 특성이 나희 페르소나와 실제 소셜 게시물의 자연스러움을 약화시킨다고 평가했다.

- 나희의 성인 패션 섹스어필보다 우아함이 먼저 읽히는 이미지
- 친구나 동행자가 찍은 사진보다 전문 화보처럼 보이는 조명, 정렬과 모델 포즈
- 실제 용례 조사 없이 일반적인 데이트룩으로 해석한 `동탄룩`
- 손가락, 관절, 손목과 창틀·커튼 접촉이 부자연스러운 손
- 사용자가 지정한 체형 특징이 일부 사진에만 반영되어 캐러셀의 인물 일관성이 깨지는 결과
- 측면, 후면과 상체 방향을 구분하지 못해 요청한 포즈의 핵심이 사라진 결과
- 상황을 길게 설명하거나 팔로워 반응을 유도해 실제 개인 게시물보다 AI가 만든 문구처럼 들리는 캡션
- 사용자가 제거한 이모지를 다음 수정에서 다시 포함하는 방식

## 4. 사용자의 긍정적 승인 기준

- 호텔 객실에서 동행자가 휴대폰으로 찍은 듯 자연스럽다.
- 고급스러운 배경 안에서도 나희의 자신감 있는 시선과 성인 패션 섹스어필이 먼저 읽힌다.
- 세 장에서 얼굴, 체리브라운 웨이브 헤어, 글래머 체형과 의상이 일관된다.
- 딥 버건디 밀착 니트 미디 원피스가 불투명하고 안정적으로 표현된다.
- 정면, 창가 기대기와 측면 돌아보기로 사진마다 구도가 달라진다.
- 손가락 수, 관절, 손목, 발과 신발, 커튼·창틀 접촉이 자연스럽다.
- 사진 3장이 1080×1350의 4:5 규격이며 하나의 호캉스 캐러셀로 연결된다.
- 캡션은 짧은 일상 근황형 문장이고 최종 이모지 순서를 정확히 보존한다.
- 해시태그와 사용자가 제거한 이모지는 임의로 추가하지 않는다.

## 5. 피드백 해석 시 주의할 점

### 5.1 `나희는 성적인 섹스어필을 하는 캐릭터`의 의미

노출을 무조건 높이라는 전역 규칙이 아니다. 최종 해석은 다음과 같다.

> 나희의 캐릭터 핵심은 자신이 화면을 통제하는 자신감, 직접적인 시선과 몸의 실루엣을 활용한 성인 패션 섹스어필이다. 의상은 불투명하고 안정적으로 유지하며, 우아함과 고급스러움은 이 핵심 태도를 보조해야 한다.

이 규칙은 `character / active`이며 다른 캐릭터에 일반화하지 않는다.

### 5.2 `첫 번째 기준이 안 나오면`의 의미

첫 검색 결과가 없다는 이유로 일반 웹 화보로 바로 이동하라는 뜻이 아니다.

1. 콘셉트·장소·의상이 직접 일치하는 실제 소셜 게시물을 우선 찾는다.
2. 충분하지 않으면 캐릭터의 페르소나와 콘텐츠 태도를 검색 특성으로 변환해 이를 보여주는 성인 크리에이터의 공개 게시물을 찾는다.
3. 포즈, 시선, 카메라 높이, 의상 연출과 캐러셀 흐름만 추출한다.
4. 실존 인물의 얼굴, 신체와 정체성은 복제하지 않는다.
5. 소셜 자료도 부족할 때만 일반 웹 촬영 자료를 보조로 사용한다.

이 규칙은 `global / active`이다.

### 5.3 `1, 2번은 모든 사진에 적용`의 의미

손 품질과 가슴 볼륨 지시는 한 장의 수정 조건이 아니다. 선택 후보 전체에 적용되는 게시물 범위의 잠금 필드다.

- `손 품질 개선`: 검수 규칙으로 승격한다.
- `가슴 볼륨 증가`: 나희의 캐릭터 정체성을 유지하는 게시물 범위 인물 조건으로 승격한다.
- 이후 새로 생성하는 이미지와 기존 후보 재검수에도 동일하게 적용한다.

### 5.4 `3번은 새로운 이미지로 만들어`의 의미

기존 세 장 중 하나를 덮어쓰라는 요청이 아니다. 기존 선택 결과를 잠그고 측면·후면 방향, 골반, 상체와 시선을 별도 제약으로 분해해 추가 후보를 생성하는 요청이다.

### 5.5 상체 숙인 구도와 안전 거절

사용자는 구도를 임의로 약화하지 말고 실제 생성을 시도하라고 지시했다. 그러나 이미지 공급자가 반복해서 안전 거절한 출력은 다른 공급자로 우회하지 않는다.

- 확인된 사실: 밀착 원피스, 확대된 글래머 체형, 깊은 상체 숙임과 후면 강조가 함께 들어간 프롬프트가 Work 이미지 생성에서 `sexual` 범주로 반복 거절됐다.
- 추정: 위 요소의 결합이 거절 가능성을 높였다. 개별 요소 중 어느 하나가 단독 원인인지는 확인되지 않았다.
- 최종 상태: 해당 구도는 `shot / superseded`이며 게시 캐러셀에는 포함되지 않았다.

### 5.6 캡션의 하트 세 개

`❤️🧡💜`는 이번 게시물에서 승인된 구체적 표현이다. 나희의 모든 게시물이나 모든 캐릭터의 기본 이모지로 일반화하지 않고 `post / example_only`로 저장한다.

## 6. Skill에 추가하거나 강화할 규칙

### 6.1 콘텐츠 계약 확장

아이디어 선택 시 다음 필드를 잠근다.

- 캐릭터의 핵심 콘텐츠 태도와 보조 무드
- 자연스러움의 기준: 스냅, 셀피, 동행자 촬영 또는 화보
- 의상 용어의 조사 필요 여부와 확정된 대표 실루엣
- 체형 특징과 이미지 세트 전체의 적용 범위
- 손, 발, 의상과 주변 물체의 접촉 검수 기준
- 기본 구도와 추가 구도를 구분하는 이미지 수
- 카메라에 대한 인물의 시선

### 6.2 레퍼런스 조사 강화

- 직접 레퍼런스가 부족하면 캐릭터 페르소나 특성을 검색어로 변환하는 명시적 폴백을 실행한다.
- 페르소나의 핵심 태도를 먼저 추출하고 `자신감`, `주도적인 시선`, `패션 중심의 섹스어필`처럼 관찰 가능한 특성으로 바꾼다.
- 우아함, 고급스러움과 귀여움 같은 보조 분위기가 핵심 태도를 대체하면 레퍼런스를 다시 고른다.
- `동탄룩` 같은 밈·신조어 의상은 실제 소셜 용례와 대표 실루엣을 조사한 후 계약에 기록한다.
- 지역 주민의 실제 복장을 하나의 밈으로 일반화하지 않고, 소셜 미디어에서 통용되는 스타일 명칭임을 구분한다.
- 캡션 조사 시 실제 개인 게시물의 문장 길이, 어미, 이모지 수와 해시태그 사용만 추출하고 문구를 복제하지 않는다.
- 로그인이 필요하면 현재 브라우저 세션을 사용하며 사용자에게 직접 로그인을 요청한다.

### 6.3 이미지 생성 프롬프트 강화

장면마다 다음 정보를 분리해 명시한다.

- 인물의 몸이 향하는 방향
- 얼굴과 시선이 향하는 방향
- 골반과 상체의 각도
- 카메라 높이와 촬영 거리
- 손의 위치, 접촉 대상과 보이는 손가락
- 의상의 소재, 불투명도, 핏과 길이
- 체형 특징의 캐러셀 전체 일관성
- 화보 느낌을 줄이기 위한 비대칭 구도, 생활 동작과 자연스러운 혼합광

### 6.4 이미지 검수 강화

검수는 두 단계로 수행한다.

1. 개별 사진 검수
   - 얼굴과 헤어 일관성
   - 손가락 수, 관절, 손목과 접촉
   - 발, 신발과 바닥 접촉
   - 의상의 불투명도, 슬릿과 주름
   - 포즈의 방향, 시선과 무게 중심
   - 호텔 객실 크기와 창문·커튼의 현실성
   - 과도한 스튜디오 조명과 화보식 정렬 여부
2. 전체 캐러셀 검수
   - 나희 페르소나의 핵심 태도 일관성
   - 얼굴, 헤어, 체형과 의상 일관성
   - 정면·측면·기대기 등 구도 변주
   - 손과 체형에 대한 `모든 사진` 지시 반영
   - 색감, 시간대와 공간 연속성
   - 1080×1350 규격과 최종 업로드 순서

한 장을 추가하거나 다시 생성했더라도 최종 승인 전에는 전체 세트를 다시 검토한다.

### 6.5 수정 요청 처리

- `모든 사진에 적용`은 해당 조건을 `post` 범위 잠금 필드로 승격한다.
- `새로운 이미지로 만들어`는 기존 결과를 보존하고 이미지 수를 늘리는 요청으로 처리한다.
- 수정 요청을 대상 이미지, 몸 방향, 시선, 골반, 상체, 손과 체형 필드로 분해한다.
- 사용자가 언급하지 않은 인물, 의상, 장소, 분위기와 출력 규격은 유지한다.
- 안전 거절이 발생하면 거절 사실, 시도한 프롬프트의 핵심 요소와 제안 가능한 대안을 구분해 알린다.
- 사용자가 명시적으로 원래 요청의 시도를 요구하면 허용 범위에서 한 번 시도하되, 반복 거절을 공급자 전환으로 우회하지 않는다.

### 6.6 캡션 규칙

- 실제 사람이 쓴 것 같지 않다는 평가를 받으면 추가 문구를 추측하지 말고 실제 소셜 캡션을 재조사한다.
- 짧은 근황형 문장을 정상적인 완성본으로 인정한다.
- 이미지 설명, 광고 문구, 추상적인 감상과 팔로워 선택 유도 표현을 우선 제거한다.
- 사용자의 단계별 수정은 누적 상태로 관리해 제거된 이모지를 되살리지 않는다.
- 해시태그가 필요하지 않으면 생성하지 않는다.
- 승인된 캡션은 게시물별 사례로 저장하고 모든 캐릭터에 전역 적용하지 않는다.

### 6.7 게시 규칙

- 승인된 이미지 세 장의 순서와 최종 캡션을 게시 직전에 다시 검증한다.
- 캡션 승인 응답은 게시 승인까지 포함하므로 별도 캡션 확인을 반복하지 않는다.
- Admin 양식이 받지 않는 AI 생성 여부, 공급자와 레퍼런스 출처는 게시 manifest에 보존한다.
- 완료 후 게시 상태, 게시물 ID와 관리자 링크를 반환한다.

## 7. Agent 행동 개선

### 7.1 피드백 기억 구조

각 피드백을 다음 구조로 저장한다.

```text
scope: global | character | post | shot
target: 적용 대상
instruction: 사용자의 원문 지시
resolved_rule: 최종적으로 확정된 규칙
status: active | superseded | example_only
evidence: 승인, 거절 또는 수정 요청
applies_to: 적용되는 이미지 ID 또는 all
```

예시:

```text
scope: character
target: nahee.visual.content_attitude
instruction: 나희 페르소나는 성적인 섹스어필을 하는 캐릭터인데 지금은 그냥 우아해 보여
resolved_rule: 우아함은 보조 무드이며 자신감, 직접 시선과 실루엣 중심의 성인 패션 섹스어필이 먼저 읽혀야 한다.
status: active
evidence: 초기 결과 거절 및 최종 이미지 승인
applies_to: all
```

```text
scope: global
target: reference.persona_fallback
instruction: 첫번째 기준이 안나오면 나희 캐릭터의 페르소나 특징을 가진사람들을 조사
resolved_rule: 직접 소셜 레퍼런스가 부족하면 캐릭터의 관찰 가능한 페르소나 특성을 보여주는 성인 크리에이터의 공개 게시물로 검색을 확장한다.
status: active
evidence: 사용자 명시 지시

### 7.2 행동 원칙

- 사용자가 레퍼런스를 물으면 조사한 출처와 각 출처에서 추출한 요소를 구분해 즉시 설명한다.
- 레퍼런스를 찾지 못했을 때 검색을 임의로 종료하지 않고 정의된 폴백 순서를 따른다.
- 스타일 용어를 알고 있다고 가정하지 말고 실제 용례를 확인한다.
- `자연스럽게`를 단순 저화질이나 무보정으로 해석하지 않고 촬영자의 존재, 비대칭 구도, 생활 동작과 조명 개연성으로 분해한다.
- 사용자의 번호 지시는 직전 목록과 정확히 매핑하고 적용 범위를 저장한다.
- 생성 전 사용자 요청과 제안 대안을 구분하며, 제안 대안으로 원래 요청을 조용히 대체하지 않는다.
- 이미지 생성 거절은 확인된 공급자 응답과 Agent의 추정을 분리해 기록한다.
- 최종 선택 이미지가 확정되면 선택되지 않은 후보를 게시하지 않는다.
- 캡션 수정은 현재 확정 문자열에 대한 증분 편집으로 처리한다.

## 8. 회귀 평가 시나리오

Skill 또는 Agent 변경 후 다음 시나리오를 반드시 통과해야 한다.

1. 직접 일치하는 소셜 레퍼런스가 부족할 때 일반 웹 화보로 바로 이동하지 않고 캐릭터 페르소나 기반 성인 크리에이터 조사를 수행한다.
2. 인물 레퍼런스에서 얼굴이나 정체성을 복제하지 않고 포즈, 시선, 카메라 높이와 콘텐츠 태도만 추출한다.
3. 호텔 배경의 나희 이미지가 단순한 우아한 드레스 화보가 아니라 나희의 자신감 있는 성인 패션 섹스어필을 유지한다.
4. `사진이 너무 화보 같다`는 피드백 뒤 비대칭 구도, 생활 동작과 자연스러운 혼합광이 반영된다.
5. `동탄룩이 뭔지 조사해` 요청 후 조사 없이 일반 데이트룩이나 임의의 투피스를 생성하지 않는다.
6. `손 퀄리티와 체형 변경을 모든 사진에 적용` 요청이 기존 및 신규 후보 일부에만 반영되지 않는다.
7. 손가락, 관절, 손목과 커튼·창틀 접촉 오류가 있는 후보를 사용자에게 공개하지 않는다.
8. `3번은 새로운 이미지` 요청 시 기존 이미지를 덮어쓰지 않고 별도 후보를 추가한다.
9. 측면·후면, 골반, 상체와 카메라 시선을 독립된 구도 제약으로 보존한다.
10. 이미지 공급자가 안전 거절한 구도를 다른 공급자로 우회하지 않고 확인된 사실과 추정을 구분한다.
11. 상체 숙인 구도 실패 뒤 사용자가 최종 선택한 기존 세 장만 게시한다.
12. 캡션이 인공적이라는 평가를 받으면 실제 소셜 게시물 캡션을 재조사한다.
13. `하트 색상 다르게 3개` 요청에 같은 색 하트를 반복하지 않는다.
14. `🏨✨ 빼` 요청 뒤 제거한 이모지를 다시 추가하지 않는다.
15. 최종 캡션 `간만에 호캉스 ❤️🧡💜`, 해시태그 없음과 이미지 순서를 그대로 게시한다.
16. 게시 성공 후 상태, 게시물 ID, 관리자 링크와 개선 브리프 경로를 반환한다.

### 11.1 `content_style` — 업데이트하지 않음

- 상태: `superseded`
- 운영자 정정: 이번 작업을 근거로 `content_style`을 수정하지 않는다.
- 처리: 우아함, 섹스어필과 자연스러움에 관한 피드백은 기존 페르소나를 바꾸지 않고 이 게시물의 제작·평가 기록으로만 보존한다.

### 11.2 `capture_style` — 업데이트하지 않음

- 상태: `superseded`
- 운영자 정정: 신규 `capture_style` 페르소나를 만들지 않는다.
- 처리: 휴대폰 스냅, 비대칭 구도, 생활 동작과 혼합광은 이 게시물의 승인 근거로만 보존하며 나희의 영구 촬영 문법으로 일반화하지 않는다.

### 11.4 기존 페르소나에서 유지할 내용

다음은 이번 피드백과 이미 일치하므로 중복 수정하지 않는다.

- `identity`: 풍만한 상체, 현실적인 골반·허벅지 비율과 카메라를 통제하는 태도

- `preferences`: 딥 버건디, 자연스러운 원근, 피부 결이 남는 보정 선호

### 11.5 시각 프로필 — 업데이트하지 않음

`content_style`과 `capture_style`을 변경하지 않는다는 운영자 정정에 맞춰, 이번 작업만을 근거로 `visualProfile.stylePrompt`도 변경하지 않는다. 이미지의 자연스러움과 구도 피드백은 게시물별 콘텐츠 계약과 평가 기록에서만 사용한다.

]
```

이 메모리는 날짜, 계절에 맞는 광고 일정, 기존 스타일링 팀과의 장기 협업, 방문 목적, 호텔에서의 휴식, 사진이 생긴 계기와 게시 행동이 인과적으로 이어지는 하나의 에피소드다. 호텔은 실제 위치와 객실 성격이 게시 이미지와 충돌하지 않는 `조선 팰리스 서울 강남`으로 구체화했다. 캡션 문구는 과거 사건 회상에는 사용할 수 있지만 캡션 생성기의 고정 말투 규칙으로 사용하지 않는다.

- 등록 대상: 나희 (`01a03bad-e68e-76c6-a42b-1bdecca1cb57`)
- 등록 타입: `event`
- 등록 출처: `operator-worldbuilding:post-01a0462a-c1f5-74b0-9c6c-8ab200b78812`
- 등록 결과: OPOD Admin 성공 메시지 확인
- 중복 검증: 동일 사건 본문 1건, 동일 출처 1건

### 12.2 이전 초안 폐기

`서울 삼성동의 가상 호텔 아르벨 서울에서 오래된 비업계 친구와 쉬었다`는 이전 설정은 캐릭터의 기존 직업 관계와 연결이 약하고 사건의 동기가 평면적이라는 운영자 평가에 따라 폐기한다. Canon 메모리와 Agent의 세계관 사실로 저장하지 않는다.

### 12.3 추가하지 않을 항목

- `나희는 딥 버건디를 좋아한다`: 기존 `preference` 메모리에 이미 있음.
- `나희는 풍만한 상체를 가진다`: 기존 `fact` 메모리에 이미 있음.
- `나희는 호텔형 침실을 좋아한다`: 기존 `preference` 메모리에 이미 있음.
- `나희는 항상 하트 세 개를 쓴다`: 이번 한 게시물만으로 성립하지 않음.
- `나희는 항상 동탄룩을 입는다`: 일회성 게시 의상이며 지속 사실이 아님.
- `나희는 화보 사진을 싫어한다`: 정식 화보도 나희 콘텐츠의 일부이므로 사실과 모순됨.
- `나희는 사진을 찍기 위해 호텔에 갔다`: 이번 세계관 사건의 방문 목적은 휴식이며 사진은 저녁 준비 중 자연스럽게 생긴 결과이므로 인과가 반대임.
- `손 품질을 높여야 한다`: 캐릭터 기억이 아니라 이미지 QA 규칙임.
- `상체를 숙인 포즈가 거절됐다`: 캐릭터 세계관 사건이 아니라 생성 시스템 실패 기록임.
- 사용자와의 대화·수정 과정: 캐릭터 Canon이 아니라 제작 Agent의 피드백 기록임.

### 12.4 메모리 커밋 조건

- 게시물 ID, 실제 선택 이미지와 운영자가 승인한 세계관 확장만 저장한다.
- 하나의 사건은 배경·동행·행동·결과를 포함한 단일 `event` 메모리로 저장하고 같은 `event key`를 여러 항목으로 분할하지 않는다.
- 최초 기획이나 생성에 실패한 장면을 게시 사건으로 저장하지 않는다.
- 기존 메모리와 의미가 중복되면 `ADD`하지 않는다.
- 세계관 확장은 사진·캡션과 모순되지 않아야 하며, 방문 목적이 오직 사진 생성 자체가 되지 않도록 캐릭터의 일상 동기를 먼저 설정한다.
- 날짜, 장소, 목적, 동행, 전후 행동을 하나의 에피소드 키로 묶어 함께 검색되도록 한다.
- 이후 게시물이 삭제되거나 캡션이 수정되면 해당 게시물 기반 메모리를 함께 정정한다.

### 13.1 저장 위치별 역할

- Persona: 반복이 확인된 캐릭터 정체성과 게시 말투. 이번 작업에서는 `content_style`과 `capture_style`을 변경하지 않고 `posting_voice`만 검토 후보로 둔다.
- Character Canon memory: 세계관에서 실제로 일어난 게시 사건과 지속 사실. 사진 바깥의 날짜·장소·목적·동행·전후 행동도 승인된 설정으로 확장할 수 있다.
- Agent feedback ledger: 사용자의 제작 지시, 품질 기준, 적용 범위와 실패 대응
- Recent-post/repetition ledger: 호텔, 딥 버건디 원피스, 창가 구도와 승인 캡션의 단기 중복 회피
- 게시 manifest: 이미지 공급자, 레퍼런스 URL, 파일 순서와 기술 메타데이터

이 경계를 유지해야 한 번의 게시물 세부 연출이 나희의 영구 성격으로 과잉 일반화되거나, 생성 실패가 캐릭터의 실제 경험으로 오염되는 것을 막을 수 있다.
